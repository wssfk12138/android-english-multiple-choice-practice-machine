# 平板横屏 UI 整改方案 R3（整改实施记录）

核验日期：2026-09-14。反馈基线：已交付内测 alpha.89 / versionCode 89；本轮已按方案实施源码整改并完成本地构建与针对性测试；未安装、未推送、未发布。横屏卡顿修复仍按原交接暂停；本方案不宣称解决卡顿。

最终确认依据：2026-09-14 用户选择 N1A、N2A、N3A、N4A，要求输出默认由后台不设上限，附加建议仅采纳 O1、O6。D1–D7 及原 15 条明确要求继续有效。下文同时记录整改后的源码证据与尚未执行的设备级验证；不运行真实补全、不安装或跨仓同步。

## 1. 目标、范围和已有明确决定

目标是减少平板横屏中的无效卡片和重复导航，把空间交还给单词与原句，让设置入口与实际页面一致。兼顾平板竖屏、手机和大字体；保留已完成的长词单行适配、评分三按钮稳定布局及已有学习数据。

用户原编号重复，本方案重新编号 R1–R11。已经明确的要求直接执行规格化，无需再次选择：操作靠右且紧凑；真题原句不折叠；合并巩固与搜索筛选区；“今日到期”改为“每日一背”；统一设置分组背景；诊断与同步利用横向空间；删除“本句语境”展示功能；词形标签中文；翻译生成范围不受显示开关限制；设置入口进入各自独立内容。

## 5. 翻译生成、显示选择与旧数据

### 5.1 生成和显示彻底分离

新翻译按所有适用、支持的模型字段生成，显示开关只控制呈现，不改变请求内容、不清空已生成数据、不触发付费请求。当前旧生成开关即使为 false，也不能继续导致缺词形。显示选项保存后，单词详情和复习答案一致生效。

| 内容 | 来源及生成要求 | 显示规则 |
| --- | --- | --- |
| 常用释义、音标、词性 | 模型提供；人工已编辑字段受保护 | 常用释义目前强制常驻，整改后提供真实可用的显示选择；主词头始终保留用于识别 |
| 词形变化 | 模型识别语境中的当前词形，列适用变化，含中文类别和歧义说明 | 独立显示开关；不得泄漏 singular 等英文类别作为唯一说明 |
| 同义词、反义词、形近词辨析、记忆提示 | 模型尽可能提供适用内容；没有合适项允许空，不为“全部生成”编造 | 每项独立开关，关闭后已保存内容仍保留 |
| 真题原句和来源 | 来自题库实际出现记录，不能模型编造 | 默认开启；开启时不折叠。原句与模型例句分开命名、分开控制 |
| 模型例句及中文译文 | 建议每次新翻译都生成一条，并明确标记“模型例句”；目前仅无原句时生成的限制同步调整 | 独立开关，已有真题原句时也可以选择查看；不能混标为真题 |
| 本地形近词 | 词库检索结果，不是模型生成 | 与模型形近词可在同栏目分来源呈现 |
| 我的笔记 | 用户输入，不由模型填充或覆盖 | 建议补独立显示开关，旧笔记完整保留 |
| 本句语境 / contextualMeaning | 删除独立展示栏目和显示配置；新翻译不再以生成该栏目为目标 | 旧字段保留兼容，必要释义兜底暂留，避免丢失历史唯一释义 |

需同步修改批量翻译、单词补全、响应校验和投影逻辑。当前 validVocabularyEnhancements 在有原句时强制 contextualMeaning 非空；generatedExample 在有原句时被清成空对象。仅删提示词或改 UI 会造成“生成失败”或例句被丢弃，必须一起处理。

### 5.2 中文词形规范

采用“提示词规范＋入库验证/规范化＋旧数据读取兜底”。覆盖单数、复数、不可数、原形、第三人称单数、过去式、现在分词、过去分词、比较级、最高级及常见英文别名。未知类别不能原样以英文充当说明：保存原始值供兼容，界面显示“词形待确认”，只对该字段进入可控修复流程，不无限重试。

要区分语法形态和完整时态：单独的分词不能直接推断成完成时。同形多解须中文说明不确定性。`singular: corruption` 的标签可规范为“单数”，但这不代表已核实名词可数性；corruption 的具体用法须结合语义判断，不能机械编造复数。

### 5.3 旧词条迁移（已选择后台批量补缺）

已确认 D4-B / N4-A：已知英文标签先本地转换；每台设备全部本地词库中的历史缺字段词条进入一次性后台补全，不重翻已有完整内容。升级后首次进入单词本时使用当前默认 API 后台启动，小批量排队、可暂停续传；先统计待补词数与所用配置并展示进度，不阻塞首屏。缺少可用 API 时等待配置，不循环失败。两台设备重叠词可能各产生费用，不承诺同步去重。已实施后台补缺与校验；本轮仅使用合成响应验证，未发起真实模型请求。

需可暂停、续传、失败重试、去重和并发写保护，不覆盖人工释义、笔记及学习记录，不在首页启动时阻塞执行。不永久删除旧 contextualMeaning 数据。缺字段补全会增加模型耗时/费用；只关显示项不能节省生成费用。正常空值（如无适用反义词）须记录“已检查且无适用内容”，不能永远被识别为缺失反复入队。

## 8A. 模型与 API 详细重构

### 源码核实

- `SettingsView.vue:377–413` 外层 API 配置可以展开多个，详情里有连接、默认模型、高级参数、模型管理、兼容信息，容易形成长页面。重复配置使用同名 label/id，实施重构时应按配置 ID 唯一化，避免点标签聚焦其他配置。
- `SettingsView.vue:469` 模型管理是普通 section，没有自己的折叠；`styles.css:677` 仅限高 370px，`698` 搜索栏 flex 扩展。有限滚动区域不等于已做折叠。
- `SettingsView.vue:503` 输出 Token 上限是禁用输入，连同兼容说明仍占整块空间。用户要求直接移除该界面。
- 既有横屏输入设了 min-height 42px，而 OptionSheet 触发器仍 min-height 48px、width 100%；NamedModelKeys 也有整行拉伸输入。仅减某个 input padding 不能统一整个表单。
- 高级参数实际含 Temperature、推理强度和附加系统提示词；F4 首版把输出上限归入同块不准确，现已订正。

## 8B. 全安卓横屏输入框/搜索框审查

已扫描 views 与 components 的 input、textarea、select、OptionSheet，并核对相关全局/局部样式。覆盖原生应用中的页面、弹层和共享组件；系统文件选择器、软键盘内部不在 CSS 修改范围。此次为静态审查，没有读取用户输入或真实 API Key，没有真机测量；下表“候选”不得当作已经复现的尺寸缺陷。

### 通用规格草案

- 单行视觉框推荐约 36–40 CSS px 起步，文本 14–16px、上下留适量空间，所在可点击行至少 48px；真实点击区域不能仅靠外观留白假装扩大，且相邻触控区域不能重叠。必要时整框采用 44–48px，以实机可点性优先。1.35 倍字体时按行高增长，不裁切中文或光标。
- 高度统一针对同类单行控件，input、select、OptionSheet、搜索框及同行按钮一起对齐；不能把文章、笔记、AI 多行输入压成单行。
- 短字段如年份/题号约 80–112px，词性/协议/推理强度约 140–220px，名称约 180–280px，一般搜索约 220–320px，地址约 320–480px；使用 max-inline-size 与可用宽度约束，不按内容逐字伸缩导致页面跳动。
- 输入值超长时保留完整内容和光标滚动；静态摘要可省略但提供完整查看。地址/密钥不能变更数据长度限制或截断存储值。
- 多行编辑按内容增长并设合理上限，长文有足够编辑面积；文件上传展示按钮＋可换行文件名，不隐藏所选文件。
- 全局规则只作用于 Android 横屏，专项字段优先，手机小横屏/分屏和软键盘弹起时允许换行。不得用无条件 input { width/height } 污染单选框、复选框、音频滑块和隐藏上传控件。

N5 的准确含义是应用默认不主动施加输出 Token 限额；不是承诺模型、上下文窗口或服务商无限输出。允许省略的协议不发送 max_tokens / max_output_tokens / maxOutputTokens 等字段；清查翻译、补全、助手及其他实际模型调用链，避免旧配置和任务硬编码重新注入默认上限。存量数值可保留用于数据兼容，但不得继续成为默认请求限额。N3 对旧 Temperature/提示词的保留不扩展到旧输出上限。

协议确实要求数值时，实施时根据对应协议官方契约和可靠模型能力信息自动处理，使用可支持的输出范围；不能发送虚构的 0、无限大或凭空选择统一常数，也不能静默回退原来的 4096/64000。能力信息无法可靠确定且服务端拒绝省略时，给出明确的协议兼容失败原因并记录未覆盖项，不重新展示用户上限设置，不伪称已实现全协议无限输出。这属于实施验证问题，目前不需要新的产品选择。

源码基线证据：`ai-adapters.ts:99` OpenAI Chat 已忽略 maxTokens；Responses 在有值时发送 max_output_tokens，Anthropic/Kiro 保留 max_tokens，Gemini 有 maxOutputTokens。`ai.ts:225` 仍传 Temperature，`378` AI 助手仍拼接旧 system_prompt。本轮已按 N5 调整调用链；六协议仅完成适配器序列化与合成测试，真实端点仍未验证。

N4 的启动是未来升级后的产品行为；本次不调用模型。升级标记、队列持久化和合法空结果需验证幂等，重新进入页面不能重新全库付费排队。两台设备重叠词可能各产生费用，不能假定同步会去重。
