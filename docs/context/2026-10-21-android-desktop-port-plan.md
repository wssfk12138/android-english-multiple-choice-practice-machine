日期：2026-10-21；实施状态更新：2026-10-22。**D01–D18 适用代码已落入两树，自动化核心与最终候选隔离交付已通过；两版现用桌面已部署并核验，首页及整体比例按后续反馈修正；主观体验待用户确认，未发布。** 当前结果以[实施回执](2026-10-22-desktop-port-implementation.md)为准，下方最初调查现场保留原日期。

本文件为本轮本地规划的权威入口，包含私有工作树位置，不直接复制到公开仓库。配套[差异与源码基线](2026-10-21-android-desktop-port-audit.json)记录实际文件 SHA-256；[Alan 来源核查](2026-10-21-alan-source-review.md)记录音色来源、对话依据与许可歧义。

## 1. 已确认的目标、范围与完成标准

用户已确认：以当前 Android 横屏的功能和交互为主要来源，补齐 Windows **内测开发树和公测发布树**；“Web”指电脑应用使用的网页界面与本地浏览器入口，不建设独立云端产品。最初阶段只调查并写方案；用户后续明确授权按方案继续开发，当前实施与验收见上述回执。

用户进一步确认：公测既有启动阻塞须先在隔离副本复核，未解决不得交付；若实际需要改正文或改变启动保护策略，再基于具体复核结果决定。音色在查过近期对话和上游来源后，以用户最后决定为准：**保留 Alan 本地离线英音，不执行中途提出的换声和重新选型方案**。许可有歧义如实记录，不以本地使用决定推导已获明确再分发许可，也不据此阻断本轮规划或本地移植。

本次允许规划的变化：缺失的学习能力、相关后端语义、横屏功能的桌面布局、Web 缩放、与这些变化有关的迁移和交付链。必须保留：Windows 文件处理、键鼠操作、任意窗口方向、两渠道各自的数据与发行机制、现有题库/练习/单词/人工编辑，以及已完成的导入与每日一学改进。Android 手机竖屏重做、云账户、云同步、全新 UI 主题、FSRS 升级、整仓统一不在范围内。

将来的完成标准是：两棵电脑树都实现下文 D01–D18 的适用目标，P01–P07 不回退，K01–K05 保留各平台/渠道职责；前端、Python 后端、数据库结构和安装资源来源一致；两版真实用户入口各通过一次完整关键链路。不能仅更新 `frontend/dist` 就声称前后端移植完成。提交、推送、正式发布及修改真实数据分别依据授权执行，不由本方案自动触发。

## 4. 移植结构与前后端接口策略

沿用 Vue 3/TypeScript/Vite + FastAPI/Python/SQLite。浏览器只调用同源 `/api`；数据库、模型调用和语音合成都由电脑后端负责。Android 的 TS/Java 只作为行为参考，不进入 Windows 运行依赖。无需引入 Capacitor、云数据库或新组件库。

采用“**一份行为清单，两套平台实现，两个电脑目标逐项落地**”。纯函数/类型/组件可按文件核查后复用；Android SQL 与原生桥译为 Python 服务及迁移；OS/渠道能力通过小型适配模块保留。不要为了这次移植搭建大型跨平台框架。

每个能力的交付单必须同时列：需求 ID、A 来源文件/哈希、W/P 基线哈希、前端变更、API 变更、数据库迁移、平台保留项、对应测试、产物资源。没有后端依赖的 UI 项明确标“无”，不能默认所有项都是纯前端。

| `GET /vocabulary/request-status`、`POST /vocabulary/request-runs` | Windows 拟新增；对齐 Android 的 pause/acknowledge/continue/retry/retry-all | task 必须 translation/enrichment；命令 ID 16–80 字符；entry_ids 去重校验；acknowledge 需 confirmed，只解除指定未知记录，不自行发送 |
| `/vocabulary/translation-runs`、`/enrichment-runs`、`/{id}/retry` 等 | 现有入口保留，转到同一个新调度器 | 禁止新旧 worker 同时工作；兼容旧请求字段，自动触发不扩张正在运行批次 |
| `GET /question-banks/imports/staged`、`POST .../staged/resume`、`.../staged/discard` | Windows 拟新增 | stage_id 由后端产生，只引用隔离暂存目录；注册在 `/{job_id}` 动态路由之前；删除仅清该 stage |
| `GET /speech/status`、`POST /speech/synthesize` | Windows 拟新增，非 Android 原生接口照搬 | status 返回引擎/模型版本、可用口音；synthesize 接收 text/accent/request_id，返回 `audio/wav`；失败返回受控错误而不是供应商原文 |

新接口用 Pydantic 入参和 TS 出参定义，增加契约样例与非法输入例；保持现有 FastAPI `detail` 错误习惯，新增机器错误码须在 `api.ts` 统一兼容，不能借机全站换错误格式。明确 400/422 输入错误、404 对象消失、409 状态冲突、413 大小超限、503 资源不可用。旧字段不删不改型，新字段增量加入。共享业务测试使用同一组 JSON 夹具，A 与 Python 的输出在忽略平台身份/时间编码后按语义比较。

### 4.2 学习查询、身份与迁移

1. “新词”严格使用最后一条 `mode=scheduled` 的记录，按可解析时间和 id 确定顺序；无记录、again、know、历史 hard 均保留，fluent 才排除；最新时间异常保守保留。浏览、发音、手动 mastered 和额外巩固都不能直接替代正式评分。新词按加入时间倒序，稳定身份/id 打破同秒平局。全部/当前题库和 search 条件沿用既有作用域。
2. 保留现有间隔表与评分命令格式。W/P 有 legacy `mastered` 兼容差异，迁移前用历史夹具明确保留规则，不把旧记录改写为 fluent。时间统一在边界解析为 UTC 比较，覆盖现有本地无时区文本、UTC Z/offset、同秒和异常值；不把所有历史日期直接追加 Z。
3. D07 推荐为 Windows 增加本地随机数据库身份、题库身份、词条不可变身份和内容 revision；由真实迁移一次性建立并补全，不按 normalized_term 伪造新身份。词条删除后再建须新身份，迁移重复运行不重发身份。catalog/detail 使用同一身份；scope 包含库身份/题库身份/筛选/搜索/排序版本。换本地数据目录产生独立 namespace；本地身份不进入 LAN/ESQ。
4. 前端继续使用轻量目录、按需详情、已有阅读位置与邻卡预取；筛选快速切换使用 generation/token 防旧响应覆盖。只有确认身份匹配才恢复滚动；未知旧 scope 可重新打开范围，不清全部 localStorage。内容变动增加 revision，普通读/发音不增加；评分改变筛选时需触发相关 revision。
5. 新增索引须用查询计划和真实 schema 夹具验证，例如 `(entry_id,mode,reviewed_at,id)`；现有函数排序能否用索引以实际计划为准，不能仅声明“有索引就快”。列表 summary 投影先保持现有完整出参兼容，明确消费者后再启用裁剪。

迁移使用 Windows `database.py` 既有 `app_migrations`/迁移入口，不拷贝 Android 整份 schema。新增表/列/索引独立编号，先 prepare、后事务写入、提交后校验；新库、两渠道旧库、迁移第二次运行都要成功。迁移不重置学习状态、不回放历史评分、不默认解锁或锁死人工数据。

### 4.3 词汇请求调度与模型结果写回

把 A 的 `vocabulary_request_runs / members / attempts / gate` 语义移植为 Python 持久服务，复用现有模型客户端、密钥解析和 `vocabulary_enrichment_jobs`。数据库是事实来源，线程锁只做补充；多标签页、重复 HTTP、重启均不能创建第二条发送路径。

事务顺序：校验命令及作用域 → 固化候选集/配置指纹/词条内容指纹 → 原子 claim 与额度检查 → 持久化发送 intent → 发送前再校验停止/配置/内容 → 记录 inflight 后一次发送 → 校验响应 → 在同一事务写词条、补缺状态和 attempt 结果。不能在数据库长事务中等待网络。

继承源端上限：翻译每批最多 8 词、翻译与补缺共享每段最多 4 次请求、每段最多 10 分钟、单次总期限 240 秒、响应最多 4 MiB；不跟随重定向、不底层自动重试。具体 FastAI 域名匹配、连接/读取超时沿当前词汇专用策略，其他 AI 功能不受此次修改牵连。配置指纹不包含可回显的原始 Key，变更 Key/模型/地址会使旧批次停止。

恢复必须区分：明确未发出的 intent 可转为未发送；无法证明未发送的 intent/inflight 标 unknown 并停止，不因启动、打开单词本或离开练习就重发。旧版遗留 translating/inflight 缺发送证据时也保守标 unknown；queued/pending 保留。明确失败可按对应入口重试；用户确认重试未知批次前提示可能重复费用。迟到响应仅在 attempt、配置和内容身份仍有效时写回，否则记安全类别并丢弃写回。

关键整改落点是两树 `main.py` 的启动恢复：当前有把 inflight/translating 直接回 queued 并启动线程的路径，启用新调度器时必须一并替换。不得只增加 request-status 接口而留下旧线程。`retry-all` 的范围、运行中合并、unknown 是否可被显式指定重试，按源端测试逐项翻译；笼统“全部失败重置 queued”不合格。

模型校验覆盖词形原值/中文标签、目标词在完整例句中出现、中英例句成对、长度限制、截断、JSON 解析失败和原句语境绑定；有真题原句仍允许保存独立生成例句。写回同时比较所有相关字段/版本，保护同秒人工编辑、删除后重建和同步更新。日志只保存固定错误类别、计数和非敏感 ID，不记录 prompt、Key、供应商正文或私人句子。

### 4.4 离线发音：共用本地服务和浏览器播放器

当前选型：继续 Alan medium INT8 英音 + 现有 LJSpeech 美音，优先锁定与 A 一致的 Sherpa-ONNX 1.13.8；Windows 实际 wheel/DLL、模型包与打包兼容性须过 G1，未验证前只是技术路线。A 的 Java `OfflineSpeech` 保持原样。

拟新增 `backend/app/services/speech.py`、`routers/speech.py` 和 Windows `src/services/pronunciation.ts`；复用按钮外观和 owner/request 状态约定。Python 合成在单独受控 worker/进程完成，避免阻塞 FastAPI 或 SQLite；浏览器以 fetch POST → Blob → HTMLAudio 播放，文本不放 URL。限制与词条输入一致的词/短语范围及总长度，拒绝路径/SSML 指令型输入；无模型时明确不可用，不偷偷回退联网或系统缺失音色。

三处入口：单词详情、每日一学、每日一背/额外巩固卡。英/美按钮在音标区域，加载/播放/错误态一致。一次只播一个请求；新点击、换词、离开页面先暂停旧 Audio、取消旧请求并递增 token，迟到 Blob 不播放，释放 object URL。浏览器自动播放限制以真实点击链验证；若异步生成后被阻止，保留音频并给原按钮再次播放，不宣称已出声。多标签页通过 BroadcastChannel 通知停止本机同应用旧播放；不把取消 HTTP 等同于成功停止后端推理。

模型进程单并发，队列只保留当前有效待播请求；过时任务丢弃，不排几十次点击。有限内存 LRU 缓存使用模型哈希+口音+规范文本作为键，先设 64 MiB 上限并测量；不将全文录音写学习数据库。初次模型加载可见 loading，加载不阻塞切词/评分；按需初始化优先，是否预热由测量决定。

准备与打包：锁定下载地址、归档哈希、解包后的 model/tokens/espeak 数据哈希、MODEL_CARD 和 LICENSE；临时目录下载、校验后原子落地，失败保留旧模型。模型不提交进源码；EXE 和发布 zip 各自明确资源目录与收集步骤，离线安装包须真正包含模型和依赖，不让用户首次播放下载。资源根从现有打包配置解析，不能依赖 cwd 或 Android assets 路径。

音质沿用用户已经确认的 Alan 选择，不再要求重新选声音。Windows 仍须做宿主播放验收：odd/respond/add/bed、长词、撇号/连字符/短语，两口音各冷/热启动；可以复用源端 66 次合成用例但不能把历史 Android 听感当作 Windows 出声证据。不裁掉词尾、不改写拼写来绕过异常。

### 4.5 导入、ESQ 与其他页面

D05 用 Python 文件暂存和数据库作业记录承接 Android 原生 stage 语义：先接收完整文件并校验长度/哈希，再建可恢复 stage；原子标记解析完成及对应 job_id；恢复返回已有 job，重复点击不再建第二份。阶段可采用 receiving/ready/parsing/parsed/failed/discarded，具体命名与现有 UI 对照后定。中断上传没有完整文件时提示重选；不能伪装可续传。解包路径、压缩炸弹、最大展开量、附件大小延用现有 ESQ 校验并在 stage 同样生效。持久化目标 profile，目标被删除时要求重新选择，不能写入恰好当前激活的题库。

DOC/DOCX/PDF 解析保留 Python/Windows 工具链，先盘点字段草稿协议再移植 UI。人工校对不被 AI 建议覆盖；模型调用失败保留原草稿。不增加 OCR 产品承诺。保留多答案附件、监听音频资产、特殊题型与 ESQ 格式 1.1 兼容；A/W/P 互导合成夹具核验题干、选项、答案、排序槽位和资产完整性。新增本地 stage、请求账本、语音缓存、续读身份不进入 ESQ/LAN。

其余页面按 D12–D17 分块迁入。A 的 `data-platform=android`/横屏条件改为内容容器与输入方式条件，Windows 窄窗仍可用，禁止带入“请横屏继续”遮罩。Windows 键鼠、滚轮、焦点与分页功能保留。界面结构变化先展示真实组件预览；不因移植顺手改变整体配色、默认折叠、文案或删除入口。

## 5. Web 界面缩放与窗口适配

### 5.1 基础约束

沿用已落地的 `applyAdaptiveZoom()`：不按屏幕物理宽度把整页缩为 62%，不全页 transform，也不通过把根字号缩小来容纳内容。`html` 以用户默认字号为基础，正文目标为正常 1rem；导航/标签可以更紧凑，但不继续用减小字号作为唯一溢出修复。

记录 CSS 内容视口、`visualViewport`、DPR、浏览器缩放和系统显示比例；物理像素不能直接当 CSS px。浏览器 125%/200% 放大应减少列数和换行，不被应用 resize 逻辑抵消。系统 150% 与浏览器 150% 的组合必须实测；不以 Playwright 的 deviceScaleFactor 代替浏览器缩放验收。

继续支持正常浏览器 Ctrl+/Ctrl-/Ctrl+0 和用户字体设置，本轮不新增另一套应用缩放滑块，避免三层倍率混用。大屏靠容器宽度与栏数利用空间，正文阅读区可用 60–75ch 建议宽度，图表/题目/校对工作区按内容扩展；这些是本方案初始设计值，不冒充平台标准。

### 5.2 区域布局预算（CSS 内容尺寸，实施预览可调但不得降低可用性门槛）

| 区域 | 宽空间 | 空间不足 / 高倍率 | 必保行为 |
| --- | --- | --- | --- |
| 应用导航 | 保留电脑侧栏及原入口；低高度侧栏自身可滚动 | 先沿既有 980px 分支核查；7 个入口不强塞 11px 单行，可在同一区域分行并给内容预留真实高度 | 不删入口、不压缩阅读字号、不把新增“更多”当默认决定 |
| 单词本首页 | 容器至少约 `20rem + 35rem + 1.5rem` 时列表/详情并列；同排等高，各自有明确定义的滚动容器 | 不足时按现有窄窗语义上下布局；不把双栏 min-height 强塞进窄窗 | 列表 sentinel 放真实滚动根；末词、分页、详情操作全部可达 |
| 每日一学 | 保留词目录与主卡；正文按完整语义板块或现有连续布局分栏 | 长内容、字体放大改为单栏；目录不能挤掉词卡；缩窄不禁用学习 | 保留顺序、记忆提示、音标/发音、前后词、空态与重试 |
| 每日一背 | 词头/发音、可滚动内容、底部揭示/评分三段；主要按钮在目标常用窗首屏可见 | 低高度时优先收紧辅助间距，评分区不覆盖正文；必要页面滚动可达，不能裁切 | 揭示前后同一底部操作槽，主卡不跳动；任何字号能抵达全文 |
| 练习 | 内容与作答区域使用各自最小可读宽度；依据真实题型决定断点 | 不满足并排预算则纵向堆叠；答题卡/长选项独立可达 | 计时、听力、提交、暂停始终有清楚路径；不截断选项 |
| 导入/校对/冲突 | 保留工作区占宽，字段标签与编辑栏有最小宽度 | 表单变单列，按钮换行；确需二维数据的冲突表可容器内横滚并有视觉提示 | 80 条冲突、长文件名、错误详情、底部批准按钮可达 |
| 模型/密钥/助手弹层 | 沿既有 OptionSheet 中央弹层，标题/搜索/操作与列表分区 | `max-block-size` 根据可见高度；列表 `min-height:0; overflow:auto`；键盘/缩放后重算 | 焦点可见、Esc 关闭并回到触发点、错误不被裁切，长 URL 不撑宽 |

实现原则：容器 `minmax(0,1fr)`、合适的 `min-width:0/min-height:0`、`overflow-wrap:anywhere` 用于 URL/长值；不用全站 `overflow:hidden` 隐藏失败。高度优先动态视口单位并留现有变量兼容回退；`visualViewport` resize 与窗口 resize 不形成循环，安全区不重复扣减。固定底栏要真实保留空间。transform 仅用于局部切词动画，不改变整页坐标；弹层统一 Teleport 与层级，开启时有明确滚动锁与关闭恢复。

### 5.3 缩放和交互验收矩阵

常用内容视口：1920×1080、1536×864、1366×768、1280×720、1024×600、800×600；窄窗回退：600×700、360×640；额外低高度 1280×500。每个实际断点测前后 1px，不只测整齐的设备尺寸。以本机实际测得 CSS 大小登记，不能把屏幕尺寸直接填成窗口内容尺寸。

完整回归放 G6；开发中仅测所改区域一个宽窗、一个窄窗和一个失败态。最终采用组合覆盖而非盲目全笛卡尔积：所有主路径测宽/窄+明暗；代表窗测浏览器 100/125/150/200%；400% 或约 320 CSS px 等效宽度做回流检查，二维表格例外单独登记；系统 100/150/200% 至少覆盖可用设备上的代表组合。缺设备/宿主必须标未验证。

断言必须包括：无非预期页面横滚（容差 1 CSS px）；主要按钮不被固定栏遮挡；内容最后一行和最后一个控件可滚到；长词/路径/错误/加载/空态不截断；字体放大不丢信息；Tab 顺序、可见焦点、Enter/Space/Esc、中文输入法、鼠标选择和触摸都可用。触摸主要操作建议至少 44 CSS px 命中区，本项目设计目标不等同于 iOS pt 规范。普通正文对比度至少 4.5:1，大字按适用条件至少 3:1，不能仅以颜色表达状态。

布局截图与功能断言都要有。没有横向溢出不代表文字清楚，没有截图差异不代表点击/保存正确。使用本地 HIG 整理指导内容层次、放大回流与反馈；Web 检验补充 WCAG 2.2。此轮未声称已做官网逐条合规审计。

## 6. 两棵电脑树同步方法与数据保护

每阶段先在 W 完成一条垂直业务链，然后向 P 应用**同一行为、不同上下文的最小补丁**并跑对应检查，避免最后一次积累成整仓搬运。最终两树一同冻结，再集中打包/验收。二者分支、版本、数据目录、渠道配置、诊断、远程题库和安装身份独立。

同步前清单记录每个目标文件原哈希、来源哈希、拟采用 hunk、保留 hunk。若实际哈希与调查基线不同，停止该文件补丁并检查新增修改；不 reset、不自动拉远端、不整提交 cherry-pick。纯共享文件可以要求字节相同；平台适配文件要求契约等价与测试相同，不能把全目录一致率当合格依据。

源码工作目录隔离不等于运行数据隔离。G0/G1 先固定独立 `ENGLISH_PRACTICE_DATA_DIR`、端口、上传/暂存/音频缓存、浏览器 profile，并核查 `LEGACY_DATA_DIR`/portable 自动迁移路径，防止测试自动拷贝真实库。运行测试前禁止加载真实 Key，关闭自动 LAN/外部模型任务；服务收到请求的目标地址须能关联当前测试实例。

测试使用生产迁移建立合成库；真实升级兼容性需要时用 SQLite 在线备份到隔离位置，备份前后记录一致性、主键/外键、计数及抽样非敏感摘要。运行中的 WAL 数据库不能只复制 `.db`。授权范围内只复制/核验，不对真实库评分、导入、清理或修正文案来制造通过。

迁移失败事务回滚并阻止依赖新结构的功能；不留下“一部分表已更新”的伪成功。旧二进制能否读取新 schema 必须实测；允许加字段不等于旧启动恢复不会误发模型请求。回退优先停写、保留故障现场、新数据导出和恢复演练；恢复旧库必须说明会丢失备份之后的数据，不能自动覆盖。

## 8. 验收用例、执行工具与通过条件

### 8.1 自动化与人工边界

前端按各树 `frontend/package.json` 的 pnpm 11.9.0，类型/生产构建命令为 `corepack.cmd pnpm run build`。现有 `test:daily-study-session`、`test:desktop-ui` 可作为入口，但必须把新增回归接入明确脚本或清单；不能因 package.json 没有挂载就漏跑其他 `.mjs`。`desktop-ui.mjs` 现有 API mock 对未特定处理的写请求返回 `{ok:true}`，只能证明布局/部分交互，不能证明真实保存与迁移。

Windows 后端使用该树隔离 Python 环境运行 `python -m unittest` 的相关模块；需要全量时遵循项目 workflow 的 discover 命令。重点已有测试：`test_daily_study`、`test_desktop_vocabulary_migration`、`test_vocabulary_review_revision`、`test_vocabulary_tasks`、`test_vocabulary_enrichment_jobs`、`test_vocabulary_bulk_retry`、`test_translation_queue_remediation`、`test_imports`、`test_esq`、`test_question_label_scope`、`test_practice_snapshots`、`test_run_app`、相关 LAN/更新测试。每树先确认文件存在及差异，再生成实际测试命令，不生搬不存在的测试名。

新增测试应覆盖请求崩溃恢复、Windows TTS 资源/HTTP/取消、ESQ stage 恢复、身份与真实迁移，测试名称在实施时确定。纯逻辑可复用 A 的 `vocabulary-review-groups.mjs`、会话/滑动等；Android bridge 测试不能直接充作 Python 已验证。所有模拟服务必须明确写“模拟”，另有真实 FastAPI+真实 SQLite 合成库集成层；供应商真实调用只在有对应授权和预算时执行。

语音先约束不影响主链：热态常见单词点击至可听 p95 目标 ≤1s，冷态 ≤5s 且即时出现 loading；停止旧声音目标 ≤200ms。输入/宿主差异、冷加载资源和计时口径必须随结果写明，音质仍靠实际听感，不能单凭 WAV 时长宣布自然。

## 11. 本轮方案自身的核验与依据

核验目标：30 个能力包数量一致；每个需要移植的能力有前后端落点、验收、依赖与失败处置；两棵电脑树均为必选目标；Web 范围和 Alan 最终决定没有沿用已被用户替代的选项；现有成果、公开边界与历史公测阻塞均有明确处理。计划文件、链接与配套 JSON 完整性在本轮交付前检查。

使用依据：接口设计 skill 的契约优先/增量兼容用于第 4 节；UI skill 的个人默认、空间与布局、设计规范用于第 5 节，特别是禁止整页缩小、支持用户放大、完整承接控件；交付证据 skill 用于第 6–10 节的源码/产物/实例/真实路径绑定；PowerShell skill 用于本机只读命令与后续 Windows 执行约束。以上是方案采用依据，不是产品验收已通过的声明。

当前结论：**源码差异调查与统筹方案已完成；应用代码完成、自动化通过、安装验证、用户体验验收、公开发布均尚未发生。**
