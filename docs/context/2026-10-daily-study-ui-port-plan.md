### 3.2 等长双栏

- 卡片外框与内部区域保持规整矩形，标题、阅读区、底部导航关系稳定；“方正”不是强制宽高 1:1。
- 正文采用连续文本流的平衡双栏，阅读顺序为左栏从上到下，然后右栏从上到下。
- 不按整块内容硬分左右；长释义、长笔记、长辨析和长提示可以跨栏分流。
- 优先复用预览的 CSS columns / column-fill: balance 与必要的扁平化结构，避免引入一套手写文本拆分算法。
- 标题尽量与首段相邻；不为保持整个大分组不拆分而造成一栏长、一栏短。
- 不能以空白占位、固定空壳等高、缩小字号、截断、省略号、隐藏后半段或按列独立滚动来通过验收。
- 阅读区保持一个纵向滚动容器，完整内容均可到达，标题和导航继续可用。
- 保留选定预览的短释义通栏与窄容器单栏回退。当前产品每日一学仍保持横屏使用规则，不借此增加竖屏学习模式。
- 极端数据同样参与最终门禁。“两栏尽量相等”按真实文字底部测量，不按容器外框高度判断。

### 3.3 平移跟手

- 横向拖动尚未松手时，当前卡片已随手指连续平移；相邻卡片从对应一侧进入。不能仅在松手后播放切换动画。
- **保留已有方向：左拖上一词，右拖下一词；键盘左/右同样对应上一词/下一词。** 不按常见轮播习惯擅自反转。
- 默认采用平移，不叠加缩放层叠或新增动效设置。
- 短拖回弹，超过阈值才提交一次切词；首尾越界只提供阻尼并回弹。
- 竖向阅读滚动优先；按钮、链接、输入、可编辑内容、已有文本选择不得误触切词；多指、pointercancel、丢失捕获、窗口失焦/页面隐藏、旋转、退出后清理状态。
- 系统“减少动态效果”下仍可切词，弱化/取消过渡，不残留卡片或锁死。
- 手势与上一词/下一词、目录点击、键盘共用一致的导航约束；连续输入不能双提交、跳过单词或错存阅读位置。
- 邻卡只是展示，不得抢焦点、接收点击、重复保存进度，或让辅助技术读出两份当前内容。
- 跟手阶段不反复读取布局和请求详情；尺寸按需缓存。利用现有有界预取，不预加载全目录，不引入轮播依赖作为默认方案。

## 4. 实施范围与主要风险处理

优先改动 DailyStudyView.vue 和必要的局部内容/手势模块。允许为降低该页面复杂度提取小组件或 composable，但不要建立新的通用框架。

共享 VocabularyMemoryContent.vue 仅在复用静态渲染所必需时修改；默认兼容旧调用方。dailyStudy.ts 仅在真实邻卡接入或导航一致性确实需要时做最小改动，并为改动增加会话测试。保留原有目录冻结、缓存上限 5、最多 2 个邻词预取、稳定身份、存储上限与刷新保护。

重点风险：

- 当前 select() 开始时就设置 index，成功后才更新 entry 和 stable。因此不能把 index 改变当成加载成功，也不能先滑走旧卡再把错误状态当成成功。
- 手势中途与刷新、慢请求、404、身份不符、旋转、离开重叠时，只有仍有效的请求可以提交；邻词失败时保持可恢复的当前状态/错误提示，不显示错误单词或写错进度。
- 原 capture/restore 包含折叠状态：移除每日一学折叠状态部分，同时保留按身份和范围恢复滚动位置的逻辑。
- CSS display: contents、columns 在 WebView 与浏览器中可能有差异；结构可访问性用语义检查保护，视觉兼容性留在 G5。
- 现有测试使用 dispatchEvent 构造触摸事件，不能单独证明真实手指事件链可用。补充浏览器原生输入驱动和获授权设备上的真实输入链证据。
- 未复现前不得把某个 pointer 处理器直接定性为缺陷。先以事件/状态日志形成直接证据，修复后移除临时诊断输出。

不改数据库结构、身份迁移、复习计数、掌握度、到期时间、翻译/生成队列、供应商、同步协议或 Windows 实现；不得为本轮 UI 自动调用付费生成或污染用户词库。测试样本仅进入隔离测试环境，不能写入生产数据来凑验收样本。

冻结候选源码与产物标识，随后进入唯一的视觉验收阶段 G5。

### G5：最终视觉验收与用户确认（全部视觉任务集中于此）

按以下顺序完成：

1. 对冻结候选运行全部适用自动检查，包含此前延后的视觉/几何套件和相关单词本回归；最终执行 `node tests/run-all.mjs --strict`（在 frontend 目录）。核对实际清单、数量、失败与前置缺失，不能沿用历史测试数，也不能接受零匹配成功。若发现无关既有失败，记录基线与直接证据并报告阻塞，不自动扩大为无关修复，不将其改标为通过。
2. 模型有能力时，查看候选运行截图/动态过程，对照选定 HTML；只能将确实检查过的项目标为通过。没能力查看的部分列入用户清单。
3. 提交一次完整的用户验收包：候选版本、入口路径、样本定位、主题/字号/窗口条件、每项操作和通过标准、截图或录屏证据位置、自动检查结论及未覆盖事项。
4. 用户完成全部待人工视觉验收。顺滑度、舒适度、信息密度、记忆提示是否足够醒目和“方正”的主观判断必须由用户确认。
5. 用户反馈不合格即 FAIL；不能把“未回复”视为接受。修复后重跑受影响检查，更新候选标识，再统一做最终视觉验收。

PASS：自动化没有失败或未说明的跳过；真实加载与用户路径证据完整；所有必须由用户处理的视觉项均明确通过。否则保留具体待验项和 WAIT_USER，不写“全部完成”。

## 6. G5 自动视觉矩阵与硬标准

### 6.1 样本与环境

至少覆盖选定预览的七组样本：真实 adverse、真实 Consequently、超长双语例句、单块超长提示、所有字段很丰富、仅有释义、长词与连续长串。前两组是历史平板内容摘录，其余是构造样本；不用标签代替检查实际数据。另补全字段同时极长、词形/本地形近词边缘数据、缺失可选字段；不得把真实用户词条原文写入公开测试文件。

基础尺寸/字号矩阵沿预览使用的 CSS 视口：

- 1205 × 728，字号 100%；
- 960 × 600，字号 150%；
- 1440 × 850，字号 125%。

选定布局全部样本运行上述三组；丰富内容、超长提示和最长正文再覆盖深色主题。额外覆盖双栏/单栏断点两侧与实际 Android 横屏视口；断点附近不通过缩小整个截图假装小屏。字体倍率应作用到真实排版，不能仅 CSS transform 缩放画布。

### 6.2 硬门禁

| 检查 | 通过标准 |
| --- | --- |
| 真实文字平衡 | 双栏分别取可见实际文字行的最底坐标，按 CSS 坐标归一化；正文和提示分别测量。两栏底差不超过该区域实际最大正文行高的 2 倍。不能用两栏容器高度比较 |
| 参照约束 | 同样样本、视口和字号下，不得显著劣于已选预览；超过预览底差 1 个实际行高需说明并修复/交用户明确判断，不能自动放宽门槛 |
| 极端内容 | 长组允许断开后仍满足平衡约束，文字/列表内容完整，无整块硬塞造成长空尾 |
| 内容完整 | 展示文字与真实字段一致，译文、出处、词形说明及本地辨析均保留；所有尾部可滚动到达 |
| 溢出 | 页面和阅读区无非预期横向滚动；长串能换行；字符、标签、按钮不裁切 |
| 结构 | 外框规整，标题/底栏可用，无双列各自滚动或因邻卡叠加增高；无折叠/隐藏入口 |
| 顺序 | 记忆提示在最显眼的首位；左右阅读顺序与固定优先级一致，无标题孤立后导致内容归属不清 |
| 交互区域 | 当前导航、上一词/下一词、返回/退出在最终支持尺寸和字号下可操作 |
| 动效 | 抬手前持续平移；无缩放层叠、跳闪、拖动后卡片留白或残留邻卡；减少动态效果有对应结果 |

说明：等长不是逐像素绝对相等，文字按行排版存在离散差异。已选 HTML 的历史最大正文底差约 63.44 CSS px，只是比较线索，不能作为新实现直接通过的依据。“2 个实际正文行高”是本轮拟定的严格技术门槛；通过自动测量后仍必须接受用户对明显不平衡的否决，不能用数值压过视觉判断。没有第二栏的短释义/窄容器用例标注“不适用双栏差值”，同时验证正确回退和内容完整，不混入双栏通过数量。

## 7. G5 交给用户的最终验收单

执行模型应把下表转换成针对最终设备和实际样本的操作单，填入入口、词名/样本编号及候选版本；不能把定位工作全部推给用户。无法自动执行的视觉项全部追加到此表，不能遗漏。

| 用户操作 | 预期结果 |
| --- | --- |
| 从单词本进入每日一学，打开有记忆提示的词 | 最先注意到记忆提示；音标、词性清楚；信息密度合理、没有大片无意义空白 |
| 看普通词及丰富字段词，从左栏读到底再读右栏 | 顺序自然、内容归属明确，两栏尽量等长，卡片规整 |

| 返回单词本与复习卡，各查看一个有丰富内容的词 | 其他页面的显示设置、展开方式和原有布局没有意外改变 |

若真机触摸、安装加载或其他功能证据也需要用户完成，单独列为“设备功能补验”，与视觉表一起在最后交付，但不得以用户说“好看”推导所有功能通过。

## 8. 测试执行规则与最终回执

- G1–G4 运行经分离后的非视觉脚本，命令以实际脚本名为准；不编造已有 package script。

1. 源码：目标工作树、HEAD、相关差异清单及候选源码指纹；存在未提交改动时不能只记录 HEAD。

6. 回退安排：保留修改前基线和已验证候选；本地提交需单独授权。不得清理既有未跟踪成果来“恢复干净”。
