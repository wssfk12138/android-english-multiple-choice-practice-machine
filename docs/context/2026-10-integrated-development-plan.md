## 3. 已定要求与本方案的工程建议

**已由用户确定的产品要求：**

- 每日一学放在单词本“每日一背”旁，仅 Android 横屏启用；采用 A 的顶部导航、双栏精读、正文整体纵向滚动。
- 沿用进入时题库范围、筛选和搜索，保存浏览位置；阅读不改变掌握状态与每日一背复习安排。
- 默认展示全部已有栏目，允许临时收起；空栏目不占位，不强制每日数量。
- 最终方向以 UI 续接对话为准：**左滑到左侧前一个词，右滑到右侧后一个词**。这取代早稿中相反的手势表述。
- 练习计时退出即停，重新打开继续计时；保留此前累计用时。

**推荐采用、但尚未实装的工程规则：**

- 自动暂停与手动暂停分开；自动暂停返回后续计，手动休息仍等用户继续。
- 翻译与补缺保留各自任务类型，共用持久停止、请求审计和去重规则；首版本应用本实例可观察的词汇传输合计最多一个在途。进程结束或断网后供应商是否仍在生成不可证明，不能承诺供应商端严格串行。
- 超时和中断进入“结果未知”，停止后续请求；用户重试必须明确对象与任务类型。
- 首版遇到任一模型解析或必需字段失败，即保存有效结果并停止本次后续请求。之后再用数据评估是否适合放宽阈值。
- 用词数、请求次数、运行时长等可执行限制控制暴露范围；不声称 Token 台账、输出上限或客户端断开能保证供应商费用硬上限。

这些建议服务于已提出的问题，不据此新增整套模型管理页面、改变默认模型、删除学习栏目或重做现有单词本。

## 4. 根因、保留的不确定性与不采用的旧建议

### 4.1 练习计时

当前 `PracticeView.vue` 保存 `elapsedMs + startedAt`，显示时加上现在与旧起点的差值；恢复时原样读回 `running`。路由离开和卸载只清界面刷新、执行词汇退出事务，未结算计时；后台可见性处理也只处理词汇事务。

源任务隔离复现：做题 10 分钟直接退出，模拟 24 小时后打开显示 24 小时 10 分钟；先手动暂停再退出则为 10 分钟。修复重点是持久状态和生命周期，清除 `setInterval` 本身不足以修复。

### 4.2 翻译与补缺

FastAI 同配置 8 词对照：60 秒读取等待在 60.022 秒超时；另一次独立请求将等待延至 180 秒，在 86.730 秒成功返回，8 词均通过校验，供应商报告 9,767 Token。这证明存在长生成与客户端等待不匹配；不能证明第一次超时请求最终是否完成、实际费用是多少。

当前源码另有直接缺口：主队列忽略翻译函数成功数量，零有效返回仍继续下一批；启动把遗留 `translating` 重新排队；补缺异常停止原因只留内存，不能与持久暂停等同；按 ID 重试忽略 ID，全量及单词重试路由还会连带重试补缺。

另一项已有隔离复现的缺陷不能遗漏：`validVocabularyEnhancements()` 复用真题原句的至少三词规则，拒绝 `go → Go away.` 这种完整短例句，导致整词生成结果被跳过。当前源码仍有这条调用链；本轮只核对源码与原复现，没有重新运行实验。它是独立缺陷，未证明就是历史事故原因，修正规则见 N3。

入口还包括 `/vocabulary/translation-runs` 对 `practice_exit/vocabulary_open` 合并全库待处理 ID，`/enrichment-runs` 的 start/resume/retry，以及数据库启动时对两类在途状态的重排。不能只修改详情按钮。旧 `translation-queue-remediation` 测试甚至断言重试 ID 1 后处理全部 250 词，属于要替换的旧行为断言，不是兼容要求。

本轮诊断没有复现 DeepSeek 历史失败，旧错误已被成功记录覆盖。修复要保存失败阶段以便追溯，不将所有历史失败都归因于这条超时机制。

## 5. 三项功能共同遵守的约束

1. **先停计时，再做退出事务。** 路由离开、系统返回、后台事件先结算计时并落盘，再处理原有词汇收集和翻译入队。后台网络等待不得继续计入答题用时，也不应成为正常退出的长等待。
2. **计时自动续计不等于翻译自动重发。** 前台返回可以恢复自动暂停的计时；翻译仍须检查持久暂停、失败停止、预算和未知请求。应用激活事件不能绕过任一保护。
3. **精读队列与复习队列分开。** 每日一学只读详情与写浏览进度，不调用评分接口，不写复习时间、不借用每日一背的到期队列顺序。
4. **详情预取不调用模型。** 每日一学只读取当前与相邻词的本地详情；读取失败的“重试”只重读数据，不能接到付费翻译重试。后台已有任务完成时可刷新详情，但不能换词、重排本次目录或重置阅读位置。
5. **成功内容与设备任务状态分开。** 词汇内容继续遵守人工编辑、上下文指纹和版本守卫；请求租约、未知状态、费用台账和暂停原因仅在本设备有效，不作为学习成果经 LAN/ESQ 传播。
6. **保留性能与视觉基线。** 沿用轻量列表、当前词详情、首屏分页等现有契约，不恢复全量详情预读，不取消原配色、背景或模糊效果来冒充性能修复。

## 6. 工作包 Q：翻译与补缺的持久保护

### Q1. 状态模型和领取

在现有词条状态之外建立设备本地运行/批次记录，优先以独立任务元数据承载 `unknown` 与运行暂停，减少对所有词条状态消费者的扩散。任务至少区分：未发送排队、发送意图已保存、在途、已处理、确定失败、结果未知；运行单独记录运行中、用户暂停、失败停止、预算停止。

请求发出前，在**同一个短事务**内校验门控和额度、领取实际仍合格的词、建立批次及发送意图并预留次数；提交成功后才发网络请求。只发送事务确认归属于该批次的 ID，不能先选全量 ID、更新部分记录后仍发送原集合。事务失败或持久记录失败则不发送；网络等待不得持有数据库事务。

记录本地 `runId/batchId/attemptId`、任务类型、词条 ID、内容版本/指纹、配置版本与时间。配置快照只含非秘密参数，Key 仍在 SecureStore；模型、协议、端点或凭据版本变更后停止旧运行，显式继续时重新建立配置快照，不在旧运行内偷换模型。两个 worker、直接调用入口和启动恢复都遵守同一个门控。

当前 `database.ts` 已有 `transaction(..., { exclusive: true })`、`dbExecutor(db)` 和 `rowOn/rowsOn/runOn`，优先复用。事务回调只用所传原始连接，不调用等待同一屏障的全局助手；不用假定 `executeSet()` 能返回逐条领取结果。迁移应先执行再允许 worker 启动，且替换两类旧在途自动重排逻辑，不能在新恢复之前先清掉证据。

本地指纹只能避免本应用重复领取，不代表供应商支持幂等。由于“保存发送意图”和“供应商收到请求”无法原子完成，进程在这段间隙消失时保守标为未知。重启只能自动恢复能够证明尚未发送的任务；旧版在途记录没有这种证据，一次迁移转为未知，保留内容而不自动重发。

迁移时已无在途记录、只剩旧 `failed` 的词保持失败，不能凭错误文字伪造请求 ID、用量或精确发送阶段；有未结束意图/未知请求则设备门控保持停止。旧用户暂停也必须继承。

### Q2. 停止、部分成功和未知结果

- 无有效结构、JSON 解析失败、缺必需字段等：保存已通过校验且通过写入守卫的**完整词条**，记录逐词原因，停止运行；未发出的词仍保持排队，不能全标成供应商失败。首版不把缺必需字段的半成品标为 ready，不引入字段级草稿或自动二次补全；有效词保存与失败词隔离即可。
- “模型无有效结果”和“模型有效但因人工编辑/删除/语境变化未写入”分开统计。并发冲突是保护生效，不当作模型输出失败；旧结果丢弃或待协调，不自动追加付费修复。
- 401/403、429、5xx、网络超时等保留 HTTP 状态和失败阶段。首版不做隐式无限退避重试；明确供应商拒绝与已发送后无响应分别处理。
- 超时、已发送后连接中断、进程消失：标为结果未知，保存供应商请求 ID（能取得时）、时间和本地批次；阻止后续请求及自动重发。
- 收到有效响应但落库失败时，单独记录“保存失败”；不能记为模型零有效，也不能自动重新付费。内容写入与对应结果确认尽可能在同一短事务中提交；能从持久记录证明已写入的词恢复为已处理，不能证明时保守停止。
- 暂停阻止下一次请求。当前请求能返回时仍允许受守卫的正常落库；若传输层无法可靠取消，界面显示“当前请求结束后停止”。客户端取消不承诺停止供应商计费。
- 普通继续不得重排未知或失败任务。原有单词重试只释放当前词及指定任务类型；原有补缺批量重试在后台捕获点击时的实际失败集合，不新增范围确认界面。未知显式重试可能重复产生费用，用户已接受该行为；现有错误提示可解释停止原因。不能以“继续”隐式重排失败/未知词。

失败停止、未知结果与用户暂停在重新进页、前台激活、重启和更改模型后都保持有效；修改配置本身不能隐式解除停止。

**迟到响应规则：** 仍对应当前 attempt、未被新尝试取代且内容守卫通过的迟到成功可落库一次，并修正该批次结果；不自动解除运行停止。已经完成的回调去重；用户明确重试后，旧 attempt 的迟到内容只能记审计，不覆盖新内容。业务超时不能释放仍在等待的本地物理请求槽；只有确认本地传输结束/被可靠取消后才可另发。重启后的远端未知保持停止；仅用户点击原有重试按钮才按对应范围重发，不新增确认控件，也不以租约到期推断供应商已停止。

### Q3. 重试与运行边界

修正 `retryVocabulary(id)`；将核心翻译重试与扩展补缺重试分开。移除 `/retry-pending`、`/:id/retry` 对另一类队列的隐式唤醒。当前词、当前筛选范围、全部失败词是不同显式操作；后端校验实际 ID 集合，不能只改按钮文案。

自动事件先入本地队列，再申请运行；只有无停止门控时才能建立有限运行。同一次自动触发冻结本段成员及请求额度，超额/后来新加入的词保留待处理。`practice_exit/vocabulary_open` 不得在已冻结运行内继续并入全库 ID。停止门控独立于 run：自动新建 run、更换任务类型、页面重进均不能绕过；用户通过原有重试按钮发起的指定范围重试允许建立独立运行，但不释放其他队列。

| 操作 | 本方案建议固定的首版语义（尚未实装） |
| --- | --- |
| 暂停 | 立即持久阻止下一请求，当前返回可保存；两类队列共同遵守 |
| 原有继续补缺 | 仅放行未发送集合，不重排 failed/unknown；未知时保持停止，通过现有错误提示说明需要显式重试 |
| 重试当前词/所选范围 | 由后端重新校验指定 ID＋任务类型，创建有额度的显式子运行；原来被停止的其他任务仍停止，不能通过全局 resume 顺带启动 |
| 结果未知：未点重试 | 默认保持停止，可阅读已有内容；重进页面/重启/继续不自动重发 |
| 结果未知：点击原有重试 | 后台在同一事务记录本次显式操作并建立指定 ID/任务类型的新运行；旧未知批次仍保留审计，未选词不重新入队。其他未知批次不妨碍这次明确的局部重试，但仍阻止自动工作和普通继续；本地传输活跃时拒绝新发 |

不新增管理页面、常驻任务卡、请求次数说明、范围确认区或未知结果处理控件；后台运行记录只用于保护与诊断。恢复原有单词本补缺状态条和 `VocabularyMaintenance.vue` 的暂停/继续、重试、模型配置入口。当前词重试只处理当前词及相应类型；旧补缺批量重试由后台在点击时冻结实际失败集合，仍受次数/时限保护。暂停造成的待处理词须可通过原有按钮继续，不能因为删掉新面板而失去恢复入口；读状态本身不启动 worker。

每次运行冻结处理范围、配置与有限请求额度，新词和另一类任务不能悄悄加入已获准运行。第一版建议默认值见第 14 节，实施时以具名常量和对应最大词数列明，不作为“最优成本”或人民币预算。达到请求/时长上限持久停止；单独点词重试不能顺便继续剩余词库。

用量缺失记为未知而非 0；使用已回传 Token 累计只能阻止后续请求，不能约束尚未返回的请求。供应商余额限制属于用户账户侧措施，不由本方案擅自修改。

## 7. 工作包 N：等待策略、协议与诊断

### N1. 先打通诊断，再调整等待

先固定内部结果契约再接调度：批次结果至少包含 `requestedIds`、`modelValidIds`、`writtenIds`、逐词无效原因、写入冲突/删除/保存失败及请求元数据；这些是**拟新增字段**，不是现有 API。当前主翻译只返回数量、补缺返回 void，无法据此区分上述结果。优先为词汇调用增加内部封装，保留其他调用原签名；逐词终态按实际请求集合对账，不能只看 `writtenIds.length === 0` 就判模型失败，也不能把补缺的提前 return 当成功。

词汇请求记录：触发来源、任务类型、供应商/模型/协议/推理配置、本批词数、请求与响应阶段、耗时、HTTP 状态、供应商请求 ID、完成/截断原因、返回有效词数、实际落库词数、失败类别，以及供应商可提供的输入/输出/推理/缓存 Token。

不只返回正文字符串而丢弃元数据；通过兼容的内部封装保留诊断信息，已有助手/错题分析调用行为继续兼容。Token 字段按供应商语义保存，推理/缓存可能属于总量的子集，不相加重复计数；人民币费用只有在已知可靠价格/结算信息时才能显示。本地记录不包含 Key、完整提示词、私有原句、完整响应正文或带凭据的 URL；沿用脱敏规范和有界保留策略。

### N2. 有界、按任务设置的请求等待

仅从翻译/补缺调用路径传递网络策略，不能全局修改 `native-http.ts` 默认读取等待。FastAI 非流式读取等待 180 秒可作为已经有对照证据的候选；它不是所有模型的固定值或成功保证。区分连接等待、读取空闲等待和一次运行总时限。

首版优先修复现有非流式路径及持久未知保护；只有确认现有 Capacitor 桥可实现所需总时限/清理语义时才复用，否则为词汇路径增加最小原生扩展，避免悬空请求与双重落库。不得把 `Promise.race` 超时包装成真实取消；逻辑超时后也必须管住仍在途的请求与迟到响应。

流式接收和真正按请求取消作为条件扩展：需供应商协议及 Android 原生传输证据，不能把一次性 `CapacitorHttp.request()` 视为渐进流。首版显示等待状态与停止含义即可，不虚构百分比或承诺仍在生成。

### N3. 格式和输入修复

- 修复 Responses 的 JSON 格式要求映射到其实际协议字段；实施时查官方协议并与所用供应商实测，不能照搬 Chat Completions 字段。
- JSON 模式只提高格式稳定性，字段、ID、例句和词形仍按现有守卫校验。不支持参数时明确错误，不静默降级后立刻再付费请求。
- 保留本地写入快照与指纹，但模型输入改为明确白名单：主翻译发送 `entryId/term/sentence`；补缺另保留已有 `commonMeaning` 供兼容合并。白名单之外不自动扩展；没有有效真题原句时发空句。`SELECT v.*` 可继续服务本地写入保护，不能整行序列化给模型。
- **修复短例句误拒绝：** 为生成例句分离校验规则，接受 `go → Go away.`。机械检查限定为字符串非空及长度界限、末尾句号/问号/感叹号（兼容引号）、目标词形按现有分词边界匹配、非空翻译和排除 Directions/Section 等说明片段；不再要求至少三词，不临时发明语法分析器，也不声称这些规则证明全部语法正确。真题原句的至少三词及来源筛选保持原约定，不通过全局放宽 `validSourceSentence()` 解决。主翻译、补缺共用同一生成例句校验，并保留缺字段/错 ID/重复 ID 的拒绝与逐词原因。
- 不静默更改默认模型或全局推理强度，不违背“不主动统一限输出”的已有决定。按模型测试批次、推理与输出质量后再评估降本。

## 8. 工作包 T：练习计时修复

### T1. 运行和恢复规则

沿用每个练习 session 的累计时间，新增版本化持久状态与暂停原因：`manual`、自动离开/后台、异常恢复，以及旧记录无法确认状态。无需为本修复变动作答数据库结构。

| 事件 | 要求 |
| --- | --- |
| 开始计时 | 页面加载完成且处于前台后，从新起点计本段 |
| 正常离开/系统返回 | 先结算累计并持久自动暂停，清除起点，再执行退出事务 |
| Home/切应用/锁屏 | 停计时并暂停听力；重复事件只结算一次 |
| 回到同一练习 | 仅自动暂停恢复，页面可操作后从新起点续计 |
| 手动休息后返回 | 保持手动暂停，等“继续练习”；不能被前台事件恢复 |
| 不计时/已经提交 | 保留不计时；提交用时固定，无后台续计 |
| 被系统结束后重开 | 只恢复已保存累计，不加最后起点到重开的离线时段 |

抽出可测试的计时转移逻辑，运行态可用单调时钟结算，墙上时间仅用于记录；明确系统时间变化时不产生负值或巨大跳增。处理路由离开被取消、异步加载返回、组件卸载及原生监听注册竞争，禁止旧页面回调恢复新 session。

### T2. 快照与旧记录

前台运行定期保存累计检查点，建议初始周期 5 秒。持久快照不能让重启继续引用旧起点：内存运行时与磁盘可恢复状态明确分开，磁盘记录当前累计与可自动恢复的原因；重启先归一化为无起点，再在前台建立新起点。异常关闭最多丢失一个有效保存周期内的时间；保存失败时不得继续承诺这一上界，应提示或记录实际失败。

旧版 `running` 没有退出时刻，不能准确恢复那段真实用时。迁移保留原记录作有限恢复依据，使用可证实的累计基数，不把旧起点一直减到当前时间。已经膨胀的累计不静默清零；首版提示历史值无法准确恢复，若提供“仅重置计时”，须局部预览并用户明确操作，保留答案、题目进度与成绩。

提交过程中仅在成功确定完成后固化 `finished`，失败应保留可恢复练习状态。听力暂停与现有计时限制保持一致，返回前台不因计时自动续计而擅自播放音频。

**恢复条件必须同时成立：** 当前 session 与路由一致、组件未销毁、内容选择/加载完成、WebView 可见、原生 app 为 active、非手动暂停且未提交；任一后台信号为假都不续计，监听初始状态未知时先暂停。监听、加载与保存带 session/页面代次校验，`pagehide` 与卸载也要幂等结算。检查点只保存实时累计，不改变界面 running、不重复添加同一段。

提交开始时暂存本段累计并暂停，成功固化这份用时；提交失败仅在上述前台条件成立且此前运行时续计。分篇提交不结束整卷计时。旧 submitted 记录即使残留 running，也不使用 `submitted_at - startedAt` 补算未知离开时段。非法 JSON、非有限数值或未知版本单独处理，保留可恢复原值、不崩溃也不猜出“正确历史时长”。因本次自动暂停出现的状态不应误显示“休息一下”遮罩。

## 9. 工作包 U：每日一学方案 A 实装

### U1. 布局与内容

从单词本“每日一背”旁进入，顶部返回/标题/范围/当前位置，紧凑横向词条导航，固定词头＋一张主体大卡＋双栏精读。左栏重点展示常用释义、有效语境释义、真题原句与来源、已有 AI 例句；右栏展示同反义/形近辨析、词形、记忆提示与已有笔记。

沿用当前主题和内容组件，A 预览双栏约 `1.3 : 1` 是参考关系，不锁死所有设备像素值。正文使用一个主要纵向滚动区；词头、导航、前后操作可达。长内容滚动而非整体缩小字号。默认展开已有栏目，空栏目省略；已校验的空辨析数组不作为补缺依据。真题来源和 AI 例句标识保留，不增加重复介绍小字，不带入预览工具栏、模拟统计或演示词条。

第一版展示已有笔记，编辑仍走现有入口；不新增评分、“学完”或强制答题步骤。`7 / 42` 表示位置，不能声称掌握或完成。

### U2. 手势与切换状态

- 左滑前一词、右滑后一词；前后按钮、键盘左右键、目录跳转方向一致，首尾不循环。
- 继承最终预览阈值：横向位移大于 72 CSS px 且大于纵向位移的 1.6 倍。触屏 `pointercancel`、多指、导航条横滑、纵向滚动、文本选择及交互控件不会误触切词。
- 使用 Vue 方向过渡和 `out-in` 顺序，transform 单段约 260ms；离场与入场是两段，不能将整次切词误报为总共 260ms。整体手感在真实触屏验收后仅作局部调节。
- 动画/当前详情加载期间保护重复切换；网络/数据错误或退出不能遗留永久切换锁。用户快速跳到另一词时，旧异步结果不能覆盖新词。
- 当前词在导航中保持可见。切回曾看过的词，在 DOM 就绪且内容展开状态匹配后恢复阅读位置；新增内容变长不强迫跳顶部。
- 系统减少动态效果时关闭位移并缩短过渡；无需手势也能通过按钮完成全部切词。

### U3. 队列、详情和浏览持久化

首次进入取得当前范围的轻量 ID/词头目录并冻结本次顺序；若范围超过当前分页，继续读取同范围的 ID 页，不把第一页当成全量。只取当前词与有限相邻词详情，缓存有界，兼容现有词汇内容版本失效规则。

目录沿用单词本的实际筛选、排序及 ID 平局顺序，但使用不带详情/出现记录的投影；不能拿 `limit=all` 的完整详情代替。分页冻结需覆盖并发变化：优先短事务取轻量成员快照，再分批展示；若桥接容量要求分批取数，使用能证明同一成员版本的游标方案。不能在 `updated_at` 变化的 OFFSET 页之间只去重便声称无遗漏。大目录不逐词挂载全量 DOM，使用可见窗口/分段导航；保留全部成员可达与正确位置分母。

保存浏览范围键、最后词 ID、位置候选及逐词阅读位置；不复用预览的 `daily-study-preview-v1` 名称，不读取示例词进度。不同题库、筛选、搜索范围不混用。退出、旋转、切后台前保存，重新进入依据最新范围匹配 ID；被删或不再符合范围的词按最近有效位置恢复，范围为空进入空态。运行期间删除当前词时安全切到有效相邻词；后台补缺改变内容或复习状态不主动重排目录。

范围键包含实际题库身份（不能仅写 current）、筛选、归一化搜索、排序及存储版本；清库/恢复数据库后校验词条稳定身份，避免数字 ID 复用串词。临时收起只在本次阅读保留，不改全局显示设置；重开按默认展开后的 DOM 将滚动值限幅。存储失败不阻塞阅读，明确续看未保存。独立学习页面不复用单词本挂载时自动翻译/补缺的副作用；测试从真实入口点击进入后的请求增量，而不只检查详情 GET。

转竖屏保留状态、显示横屏继续提示和返回；恢复横屏续看。Android 横屏判定沿用项目实际方向机制，不用一条屏幕宽度判断桌面也能开启；手机横屏入口与窄宽布局按现有“Android 横屏”要求核验。

加载、空范围、详情缺少字段、读库失败与重试、超长词/原句、大字号、快速切换、旋转/系统返回均有可操作状态。翻译失败/未知时展示已有可读内容及必要状态，修复/付费重试仍由明确的队列操作承接。

数据库迁移采用一次性门控、旧/新/空库覆盖、事务与启动链现有约束；不在引导链内部调用会等待同一引导链的 API。新增本地表/字段需明确 LAN 与 ESQ 排除或兼容映射；若触及 ESQ，执行对应 Windows 兼容检查，不能借机同步 Windows 源码。

| 题库 → 计时练习 → 返回 → 等待 → 同一练习 | 等待期间不增加；再次可操作后继续。另测 Home/锁屏、手动休息、听力和提交 |

付费验证是独立范围。本次任务只修方案，不发请求。后续核对源对话中“自行进行可控的付费翻译实验”的对象和范围；已有对应授权持续有效，不因换窗重复询问，但原实验次数和结果不是新执行记录。超出获准范围再确认。先用模拟和保存的脱敏响应验证停止机制，再做极少量真实请求；预先确定供应商/模型、词数、最大请求数、停止条件及隔离数据，结果不写用户词库。无对应授权仍可完成代码和模拟检查，明确未做真实供应商复验。

## 14. 交付、回退与后续选择

本轮计划的推荐最小交付包括 Q、N 的非流式可靠性修复、T 和 U；全功能联合验收后再讨论渠道交付。流式进度、可靠单请求取消、独立翻译模型配置、分阶段生成、自动自适应批量属于后续候选，只有当前传输需求无法满足必要验收时才将最小原生扩展纳入。

每阶段回执记录改动范围、源码及产物来源、自动化、装机观察、未验证项和授权依据。任务/日志新表涉及应用降级兼容；暂停/未知记录和迁移用户数据不能靠 Git 回退恢复。回退优先保护答案、复习记录、人工词义、笔记、计时旧备份和浏览进度，不能卸载清数据作为默认恢复。

公测同步仅在获批后逐项列源/目标文件与渠道差异；分别构建、核验数据与版本。Windows 保留独立数据库、版本、签名和发布节奏。发布前另核应用 ID、签名、递增 versionCode、APK SHA-256、更新清单及公开内容扫描。

以下是便于直接开工的保守初始值，属于工程建议，尚未通过成本/触屏效果实测定优；实施阶段可在已有授权内依据证据调整并记录。

| 参数 | 首版建议默认 | 调整依据与限制 |
| --- | --- | --- |
| 主翻译批次 | 保留现有最多 8 词/请求；补缺仍 1 词/请求 | 原建议默认降为 2 缺乏成本证据，且重复系统输入可能更贵。先修等待、校验与停止；若后续证据表明需缩批再定向调整 |
| 自动运行请求额度 | 工程建议：翻译与补缺合计最多 4 次；发送意图预留即占额，失败/未知不退额 | 纯主翻译理论最多 32 词，实际受已冻结成员和时间共同限制；混合时 8×主请求数＋补缺请求数。不是已确认产品要求或安全费用保证；到上限持久停止，新自动触发不能另建运行绕过 |
| 自动运行时限 | 10 分钟，下一请求前检查剩余额度/时间 | 运行时限不保证在途请求或供应商立即停止；不得因时限重发 |
| 连接/读取等待 | 连接保留 15 秒；FastAI Responses 候选读取 180 秒；DeepSeek 已测路径先保留 60 秒；其他保留现值并记能力策略 | 按供应商＋协议绑定，禁止全局延长；必要时根据实际错误再调整 |
| 单次词汇请求业务总期限 | 候选 240 秒，且不超过该运行剩余时限 | 剩余时间不足完整预算时直接停止，不临时缩短超时制造未知。业务截止只记未知/禁止新发，不代表物理请求已结束；需 N2 证实原生清理或迟到处理 |
| 前台计时检查点 | 5 秒 | 以有效保存周期衡量异常损失；保存失败必须单列 |
| 诊断保留 | 最近 2,000 条请求元数据且不超过 30 天，先达到的边界先清理 | 只清理已结束的诊断记录；待协调的未知任务、暂停原因不随日志清理 |
| 精读详情缓存 | 最多 7 词，当前词加前后各至多 3 词；首屏优先当前及左右各 1 词 | 有界缓存和按版本失效，不读取全词库详情 |
| 浏览位置保留 | 每范围最多 200 个词的阅读位置，最多 20 个近期范围 | 优先保留当前词；其余按最近使用淘汰，只影响旧滚动位置，不影响内容和复习记录 |

请求额度是应用可执行的次数限制，不能换算为未知供应商的人民币硬限额。新自动运行被额度/错误停止后，须明确的继续操作才能开启下一段；后台重启或反复打开单词本不算继续。涉及扩大付费范围、改变默认模型/核心学习流程、重置历史数据或新增发布目标的决定须有明确用户依据。

请求次数与总时长取先达到的边界；4 次不是承诺一定发满。时限在同一进程使用单调时钟判断，重启用持久起始时间保守恢复，时钟异常不重新赠送额度。诊断清理只涉及已终结且不被活动/未知任务引用的记录，保留必要审计关系。
