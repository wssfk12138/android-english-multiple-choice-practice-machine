## 1. 给执行模型的入口

先确定用户当前要的是审查、实现还是安装；不要把本文出现的命令当成授权。已授权实现时，从尚未完成的第一步继续，不要求用户逐步重复批准常规编辑。付费、覆盖安装、提交、同步与发布核对各自已有授权，不能相互推导。

每次只实施下表的一步。一次闭环包含该步的阅读、修改、测试与修复，不把“写完代码”当成完成。通过后可以自动进入下一步；若换窗，保存短回执。只有遇到影响产品选择、数据安全、授权或接口正确性的关键缺口才提问，普通文件命名和局部实现直接沿用项目约定。

每步只带入：适用项目规则、主方案对应小节、该步源码及调用者、一个相关测试/同类实现、上一步回执。不默认全文加载所有历史、技能、NOW 或整套源对话。行号可能变化，先按下面列出的真实符号定位。

**不得自行补出的“事实”：** 未读过的函数签名、数据库字段、供应商支持参数、取消请求能力、设备已装版本、真实测试 PASS、用户曾授权。查不到就标为待核实；拟新增符号明确写“拟新增”，与当前已存在接口分开。

## 4. 三张防误执行核对表

### 4.1 请求从哪里来

逐个确认“入队、请求启动、停止解除”三种动作。任何绕过调度器直接调用付费生成函数的路径都必须接入；不能只搜索 startWorker。

| 现有入口 | 修复时要查的动作 |
| --- | --- |
| App.vue 启动/激活 → resumeVocabularyTranslations | 仅恢复可证明未发且门控允许的运行，不清错误/未知/用户暂停 |
| PracticeView 收词、提交、退出 → translation-runs | 本地收词与网络请求分离；后端不隐式扩充冻结 ID；先停计时 |
| VocabularyView 挂载/维护与详情重试 | 读状态不发送；自动触发有统一额度；单词按钮不调用全量重试 |
| VocabularyMaintenance → enrichment-runs 的 inventory/start/resume/retry | 盘点不等于付费授权；继续与重试语义分开；不隐式解除其他阻断 |
| /retry-pending、/:id/retry、/:id/enrichment | 明确 ID/类型；重复点击有稳定 commandId 或等效去重；不存在的 ID 不扩大范围 |
| 数据库启动恢复 | 先迁移再 worker；两类遗留在途都保守未知；未发 queued 不伪造成供应商失败 |
| 每日一学入口、详情预取和读取失败重试 | 只读内容；不得继承单词本挂载时的自动维护副作用 |

### 4.2 状态与返回结果

实施 S1 前先写一张局部字段/函数映射，必须能在源码定位；不要先画一套脱离已有代码的服务框架。

| 必须回答的问题 | 正确边界 |
| --- | --- |
| 词条状态、运行停止、请求结果各存哪里？ | 词条仍服务展示；门控/请求状态在设备本地元数据；不能只新增内存枚举 |
| 这批到底发给哪些词？ | 以事务领取成功且属于本 attempt 的 ID 为准；范围和配置冻结 |
| 为什么没写进去？ | 模型校验失败、编辑/语境冲突、删除、保存失败分别记录；不能统一算 0 个有效 |
| 暂停后收到响应怎么办？ | 当前有效 attempt 可守卫落库，保持停止；旧 attempt 不覆盖新值 |
| 等待结束是否等于供应商停止？ | 不等于；本地槽与远端未知分别处理；不承诺 exactly-once 或费用硬上限 |
| 继续/重试释放了什么？ | 后台从原有按钮参数冻结 ID＋类型＋次数；其他队列仍停；未知只允许原有重试按钮显式重发，不新增确认区 |
| 本地保存失败怎么办？ | 发前记录失败禁止发送；发后保存失败停止并保留诊断，不自动付费重做 |

### 4.3 每日一学和计时的最小判据

- 计时用“10 分钟→离开 24 小时→回来 5 分钟＝15 分钟”断言；不能用 setInterval 是否清除来替代。
- WebView 与原生前台条件同时成立才续计；重复事件只结算一次，旧 load 不能恢复新页面。
- 每日一学目录冻结，详情按版本刷新；内容更新不应被错误当成“重建全部目录”的信号。
- 大目录只轻量取成员，有限详情与可见导航；不能为避免幻觉而写死示例词或只展示第一页。
- 从第 2 个词开始左滑到第 1 个，右滑回第 2 个；按钮/键盘/目录对应一致，首尾不循环。
- 观察真实入口期间请求数与复习数据前后变化；请求日志或本地状态中不写 Key/私有正文。

## 6. 停止条件、回执与续接

出现以下情况先停止该步依赖部分：预期接口与源码冲突且影响正确性；迁移/事务无法保证门控；未知请求仍可能被自动释放；必要检查无法执行；改动将越过允许范围；新的用户要求改变关键产品行为。先查小范围证据，仍无法解决再明确问缺什么，其他独立的已授权工作可继续。

相同命令/补丁形态连续失败两次切换方法；测试失败记录首个根因和实际错误，不在测试未过时推进安装。不要因自己不确定就删除测试、降低断言或增加付费实验。

实施中在已有阶段回执位置维护**一份当前记录**，每步通过后更新；不把执行过程堆进 PROJECT_INDEX 或重写全局 AGENTS。建议格式：

```text
当前步骤：S…；状态：未开始 / 实施中 / 代码与定向检查通过 / 阻塞
```
