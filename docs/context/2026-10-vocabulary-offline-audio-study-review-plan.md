## 2. 成人学习依据及产品解释

主要依据为成人二语学习和成人提取练习研究。Baxter 等 2022 年成人实验的摘要报告，114 名成人在选择任务中对照形近词时获得学习收益。它支持有针对性的辨析，不直接证明任意相似度排序、固定每组数量或中国成人考研词库的长期收益：[成人形近词研究](https://doi.org/10.1016/j.learninstruc.2022.101582)。本轮可读取摘要及检索片段，全文获取受限；不编造全文结论。

成人外语词汇实验支持先回忆再核对，以及之后再次提取；间隔练习研究支持跨时间复习，具体间隔需匹配记忆目标：[Karpicke 与 Roediger，2008](https://profiles.wustl.edu/en/publications/the-critical-importance-of-retrieval-for-learning/)、[Cepeda 等，2006](https://www.yorku.ca/ncepeda/publications/CPVWR2006.html)。儿童研究不作为本期默认规则的直接依据。

产品采用“到期候选 → 相近优先级内小组辨析 → 后续脱离小组独立回忆”。成年人可使用简明的词义、词性、搭配和发音对照；不采用幼儿式奖励、拟人鼓励或“看一遍就记住”等承诺。每组 2–3 词、候选窗口等均为工程初值，不冒称科学最优参数。

学习效果评估与软件验收分开：软件交付不等待数周学习研究。后续经同意，可用隔天/约一周无提示回忆、形近误认比例和用时评估效果；单个用户短期结果不称为统计证明。

## 4. 离线发音架构与契约

### 4.1 职责

| 模块 | 职责 | 不承担 |
| --- | --- | --- |
| 共用发音按钮组件 | 美音/英音、加载/播放/错误展示、可访问名称 | 模型初始化、下载或页面独立状态机 |
| TypeScript 发音服务 | 活动页面/词条所有权、请求编号、状态订阅 | 在 JS 主线程合成音频 |
| Capacitor 原生插件 | 检查包、提交/取消请求、发送状态 | 在共享桥接队列内长时间加载/合成 |
| 原生 TTS 执行器 | 专用单任务工作线程、模型生命周期、音频缓存 | SQLite 调度和学习状态写入 |
| 内置语音资产 | 随 APK 分发两套模型、音素数据和版本哈希 | 运行时下载、解包或改写 APK |
| 原生播放器 | 音频焦点、开始/停止、生命周期清理 | 将整段 PCM/Base64 经桥反复传给 Vue |

首版用 CPU 推理，合成并发 1，线程数先从 1 试起，是否增加由同机测量决定。优先至多一个活跃模型，缓存两种口音的已生成音频，避免默认双模型常驻；若口音切换冷启动体验不合格，再测有界保留第二模型，不直接扩大内存预算。

### 4.2 调用与状态

拟定稳定契约，命名按现有代码风格调整：

    speak({ requestId, ownerId, text, accent: 'us' | 'gb' })
    stop({ ownerId, requestId? })
    speechState: idle | loading | playing | error

返回接收确认与异步播放事件分离，事件携带 requestId、ownerId、accent、错误码。旧页面卸载的 stop 不得取消新页面的有效请求。点相同的正在播放按钮停止；点另一词/口音采用最新请求优先；切词、退出、应用退后台和音频焦点丢失停止播放。即便底层推理不能立即中止，也必须取消后续播放、抛弃旧回调，并合并待执行请求为最新一个；不能为“取消”直接释放正在使用的 native handle。

本期不提供下载或安装语音包接口：模型随 APK 分发，覆盖安装后即具备发音能力。错误区分模型资产缺失、ABI/引擎不兼容、输入不支持、初始化/合成失败、音频输出失败。取消是正常状态，不弹失败提示；用户重试有界，不自动无限重试。

约 20.1 / 19.8 MiB 只代表压缩下载；不是 APK 增量、安装占用或运行内存。发布前分别记录引擎库增量、模型解压大小、临时安装峰值、音频缓存和运行内存。

官方 [3731 议题](https://github.com/k2-fsa/sherpa-onnx/issues/3731)计划在 2.0 调整 espeak-ng / piper-phonemize 依赖。不能把计划当已发布，也不能盲目跟随 latest。G1 先锁定实际支持该模型与音素转换器的具体版本、ABI、文件哈希与许可证；任意词支持必须保留本地字素到音素转换，只有固定 lexicon 的路线不满足本需求。

[官方模型资产](https://github.com/k2-fsa/sherpa-onnx/releases/tag/tts-models)、[LJSpeech 模型卡](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_US/ljspeech/medium/MODEL_CARD)、[Cori 模型卡](https://huggingface.co/rhasspy/piper-voices/blob/main/en/en_GB/cori/medium/MODEL_CARD)。模型卡列数据集 public domain 不等于所有依赖都同许可；需核对实际分发模型、Sherpa、ORT、音素转换器的许可和告知文件。本仓 package.json 为 GPL-3.0-only；不因此跳过依赖来源与分发义务核对。

用户最终决定把美音和英音直接放入安装包，不要求额外下载；旧版本覆盖更新后直接具备发音能力。两个 Piper INT8 模型、`tokens.txt`、`model.onnx.json`、`MODEL_CARD` 与 `espeak-ng-data` 放在 `android/app/src/main/assets/tts/en_US|en_GB`，Sherpa-ONNX AAR 放在 `android/app/libs`。二者都由[可复现脚本](../../frontend/scripts/prepare-tts-assets.ps1)按上游 SHA-256 下载和复制；AAR、模型目录和 `.tts-cache` 不提交版本库。

2026-10-17 最终构建的内部 APK 为 159,794,461 字节（152.39 MiB），其中语音资产 718 个文件、解压后 74,695,709 字节、APK 内压缩后 56,639,909 字节。APK 保留 `arm64-v8a` 和 `armeabi-v7a` 两套 ARM 原生库；`x86`、`x86_64` 被 ABI 过滤器排除。ABI 是原生 `.so` 库与 CPU 指令集之间的二进制接口：现代 64 位 ARM 手机和平板用 `arm64-v8a`，较早的 32 位 ARM 设备用 `armeabi-v7a`；x86 模拟器不能安装这个包。保留两套 ARM 是为了覆盖旧设备，代价是安装包更大；以后若确认只需 64 位，可按 ABI 拆分或只保留 `arm64-v8a`。

内置资产不经过运行时 manifest 或解包器；发布构建仍须用脚本校验上游哈希、记录实际文件清单和许可来源，并在 APK 层核验模型与原生库确实存在。模型卡列出数据集为 public domain，但 Sherpa、ONNX Runtime、espeak-ng 等依赖的分发义务仍需在发布授权阶段单独核对。

### 4.4 输入、音质与缓存

朗读实际展示且用户选择的词条文本，不能把 further 静默替换成 lemma far；展示文本、按钮可访问名称和送入引擎文本保持一致。输入规范化只处理空白和明确的字符等价，不擅自改拼写。超过现有导入范围的非法输入明确拒绝；不得为 TTS 擅改导入校验。

同形异音词如 read、record、lead 的孤立文本可能无法判断语境；如无经过验证的词典/上下文发音能力，不承诺每个词唯一正确读音，也不把 UI 音标当作引擎必然使用的音素。首版测试常用词、形近词、撇号、连字符、罕见词、专名和短语；两种口音分别听审。必要时换同级候选音色，明显扩大下载/内存时再报告取舍。

音频缓存以精确规范化文本、accent、模型版本、发音参数为键；应用私有目录有界 LRU，建议起始上限 64 MiB（产品预算，待 G1/G5 测量），不放 SQLite、LAN 或云备份。模型是 APK 只读资产，不复制到可丢弃 cache 目录；缓存可以清理，清除缓存不影响发音能力。首版不主动合成全词库、不默认预热两种口音，用户请求优先于后台任务。

## 5. 每日一学筛选与评分依据、首页等高布局

### 5.1 交互规则

默认筛选“新词（尚未学习）”；普通“每日一学”入口固定传入 `status=new`，无论首页当前筛选是什么。页内保留原预览七个选项及顺序：新词（尚未学习）、全部单词、每日一背、高频词、学习中、已掌握、等待翻译。除新词范围外，六项完全沿用首页原有规则，不新增“已学习”或“已评分”选项、不用新的评分条件替换原有学习中/已掌握语义。从每日一学返回首页时把 `new` 映射为首页已有的 `all`；首页不新增可见的“新词”筛选项。若返回时页内选择的是其他筛选，则把该筛选名带回首页。

新词在此表示尚未达到本次评分门槛，可能包含加入较早、已有“不认识/认识”记录的词；按 created_at DESC 加稳定身份处理并列，展示仍是新加入的在前。显式筛选链接尊重用户选择，阅读位置按词条身份和筛选范围恢复。

移除原方案中的完成按钮、已学习徽标、撤销反馈及学习保存失败状态。进入、翻页、滑动、预取和播放发音不产生任何学习记录。每日一学只负责阅读和筛选，评分仍在每日一背进行；空范围显示“暂无未学习单词”和“查看全部单词”。

### 5.2 判定与现有数据

| 最近一次正式评分 | 是否留在未学习范围 |
| --- | --- |
| 无正式评分记录 | 是 |
| 不认识 again | 是 |
| 认识 know | 是 |
| 旧版本 hard（含旧“不认识”按钮） | 是 |
| 熟练 fluent | 否 |
| 仅额外巩固 reinforcement | 忽略这类记录，仍按正式评分判断 |

采用最近一次正式评分，不能采用“曾经熟练过”：熟练后再次不认识/认识，应重新进入未学习范围。此为本版实现口径；不新增永久学习完成状态。无评分但手动标记已掌握的词仍在未学习范围，首页“已掌握”筛选保留其原有手动/评分状态含义，不强行使两个范围互斥。

权威来源为 vocabulary_reviews 中 mode='scheduled' 的记录。当前 review_count 包含额外巩固，不能用 review_count>0 判断；last_result 由正式评分更新，但若未验证导入/同步/旧库的一致性，不单凭该缓存字段认定存在评分记录。正常无记录与读取失败必须区别：数据库失败不能伪装成全是未学习。

现有字段是 reviewed_at。按实际评分时间降序、同秒时 id 降序取得最新正式记录；不可用同步 updated_at 当评分时间。导入/同步可能存在时间字符串格式或并列差异，G1 用现有导入和同步夹具验证时间规范化及稳定顺序；异常日期不能静默挑一条 fluent，应保守保留并记录可诊断问题。词条删除/重建、换库和恢复沿用现有身份保护，不以显示文本或复用数字ID跨库关联旧评分。

不新增完成侧表、完成/撤销接口、完成 revision 或历史回填任务。旧评分直接用于只读推导，不改写历史、next_review_at、review_stage、lapse_count 或手动已掌握状态。既有评分事务、幂等 command_id 和同步契约保留。若查询计划证明需要，按生产迁移流程补覆盖 entry_id、mode、reviewed_at、id 的索引；不要在未测量前扩建通用学习状态系统。

### 5.3 目录、计数与性能

现有 daily-study/catalog 与 status 契约增量支持 new，在同一数据库查询层计算候选资格并复用定义，避免客户端逐词读历史的 N+1 查询。返回目录仍只有必要身份和文本，不把完整评分账本或详情带回前端。评分修改已触发词库 revision，复用现有版本与失效机制，不新增平行版本系统。新词范围使用独立的 `new-v1` 阅读位置缓存标识，避免旧版把 `status=new` 当作全部单词时留下的范围位置被复用；其他筛选继续沿用原 `browse-order-v1` 标识。

在进入每日一学、明确切筛选或从复习返回时取得当前资格；按身份恢复仍符合条件的项，否则选择相邻有效项，空集显示空态。活动阅读目录继续冻结，外部评分变化只标记失效，在安全的重新进入/刷新边界生效，不突然打断当前阅读。切筛选取消旧请求和发音所有权，创建新目录，旧响应不得覆盖新范围。

每日一背评分成功后只做常量级失效标记，不同步刷新全目录，不新增历史查询或排序到下一卡路径。评分写入失败则不推断为已评分；重试复用现有幂等事务。保留 5 项详情缓存、相邻预取、滑动动画和错误恢复。

### 5.4 单词本首页两列等高

仅调整已有横屏双列布局：左侧词条列表与右侧详情卡的上边界、下边界一致。当前左列表 max-height 与右详情 min-height/内容自增的组合是差异来源。使用同一网格行高度、align-items:stretch、容器 min-height:0，左右各自 overflow:auto；移除此模式下互相冲突的 max-height 与 sticky top 限制。保留两列宽度比例、筛选区、详情操作和分页哨兵。

当前预览以 max(440px, 100dvh - 280px) 给双列统一高度；这是横屏参考值，正式实现根据实际头部/筛选区及安全区确定可用高度，避免大字体换行时遮挡。不通过填空行、隐藏内容或拉长单词项制造等高。较长详情和左列表均内部滚动，底部操作可达；长词、详情编辑、空详情和错误内容也等高。窄屏沿用现有折叠/堆叠规则，不强迫显示两列。

## 6. 成年人每日一背：抽取、排序、辨析

### 6.1 评级修正与正式复习

按钮仍用简洁的“不认识 / 认识 / 熟练”。不认识映射 again（本期 10 分钟后到期重学），认识映射 know，熟练映射 fluent。hard 为旧记录/兼容 API 保留，不把历史 hard 批量改写成 again；历史评分会产生歧义，不能追溯猜测。

先保留现有间隔阶梯，修正按钮语义。显示答案后才能评分；连续点击只产生一次账本和调度更新。额外巩固维持只记巩固历史、不改变正式计划的契约。熟练仍不是永久免复习。

### 6.2 候选和优先级

仅翻译可用且已到期/无既定时间的词进入正式候选，遵守当前题库 scope。不要为了凑组拉取尚未到期的熟词、未导入词或等待翻译词。所有合法候选仍可被遍历，不新增用户未批准的每日硬截断上限。

本期保留现有“未复习词优先”的普通候选顺序，不把“已到期旧词优先”混入这次行为变化。旧词按相对逾期程度分档的排序留到单独测量：需要先确认逾期比例的定义、异常日期回退和公平性断言，再与学习效果评估一起决定，不能在本期顺手改排序。现有 `reconcileDueQueue` 的两段优先级、稳定键和持久化续背继续保留。

已到期重学词保留独立队列，先复用每 4 个普通词最多穿插 1 个的初始配额，主队列为空则正常重学。未到 10 分钟不能因为“已隔四张”提前判为正式重学；不存在普通词时展示下一次可复习时间，不制造忙等。活动期间到期检查安排在后台低频安全点和恢复前台时；不在每次评分后全队查询。

续背保留已经发布的未完成片段。新一轮候选生成兼顾等待年龄，不能让新增词或形近组无限挤占孤立词。必须有模拟多日队列的公平性断言，证明有限候选在无新增干扰时最终遍历、存在新增时老尾部也能推进。

### 6.3 形近分组规则（本期已实现）

词条身份不变，形近仅改变展示关系，绝不合并词条。复用编辑距离候选，结合词长、相邻换位、词边界与已校验的 similar_forms；相似关系不是同义关系。普通屈折变化和不同词义的易混词分开处理；短词阈值更严格，不因为同前缀/同后缀形成巨大簇。

本期采用轻量、确定性的两词组：在复习队列快照中按原顺序向前看最多 8 项，只把同一优先级段（都未复习，或都已复习且 `next_review_at` 同一天）的词配对。词形只比较英文字母，忽略大小写；长度 3–6 使用 1 次编辑距离，长度 7–24 使用 2 次；相邻换位按 1 次编辑处理，因此 `quiet`/`quite` 可配对。要求首字母或末字母相同，短于 3 或长于 24 不配对，不使用 A≈B、B≈C 的传递链。分组不新增、不删除、不重排到期词；未命中或缓存未就绪时照常按现有队列显示。

已发布片段冻结，固定当前卡和下一卡；后台仅规划未发布部分，完成后在安全边界追加。只在缓存命中且不拖慢出卡时应用分组；冷启动缺缓存使用正常到期队列，不能空白等待。降级需要可观测，但不能用永久降级冒充形近词功能交付；最终必须证明缓存就绪时确实编组。

分组身份由两个词的稳定键排序生成，不依赖当前下标；评分移除词后，组身份和已评分成员仍保留在本次复习快照中，恢复会话不重新随机。本期不改变队列顺序，配对词不一定相邻显示，因此只提供“形近词组 · 1/2”标签和组完成后的非阻塞辨析入口，不把“永远下一词就是配对词”写死。独立提取失败时下一轮仍按原队列出现，不额外推断 A→B 混淆事实。

### 6.4 辨析 UI 与学习统计

在组内词上使用轻量标签“形近词组 · 1/2”；不提前展示同组其他词的答案。各词按原流程独立显示、揭示和评分。该组均完成本次作答后，出现非阻塞“查看辨析”入口，展示两词的拼写差异、核心词义和各自美英发音；关闭为“返回复习”。用户不点时照常背下一词。若该组正好是最后两个待复习词，复习完成态保留“查看辨析”入口，用户关闭或退出后才回列表。辨析面板只在两个词都评分成功后打开，缺详情时保留已有抬头和“暂无可用释义”，不阻塞评分或下一卡。

不新增强制辨析弹窗，不把展示对照内容算成一次成功回忆，不自动给任何词增加评分或延长间隔。对照数据缺失时只展示已存在且可信内容；不在评分时请求 AI，解释尚未生成不能阻塞下一卡。对照内发音也遵循同一原生服务和退出停止规则。

## 7. 性能预算、降级和回退

### 7.1 不可突破的边界

1. 评分到下一卡绘制关键路径新增整库扫描、全量排序、模型初始化、网络请求的次数必须为 0；必要评分数据库事务继续保留。
2. 不把 similar_forms 全文本、全词库详情或 PCM 加回轻量队列投影；组关系只带少量身份和版本。
3. 相似索引按词条文本/集合变化增量更新；普通评分、翻译说明和音频播放不清空整份索引。计算在 Worker/专用执行器，数据库访问仍需分批、低优先级并让出评分通道。
4. 构建期资产校验和运行期语音合成不得占用 Android UI 线程或共享 CapacitorPlugins 执行器做长工作；不撤销 LAN 线程隔离。
5. 不以“后台”“异步”几个字代替性能证据；CPU、内存、数据库锁和 IO 仍可能竞争。可复用缓存不能无限增长。

### 7.2 测量与初始门槛

G0 只做小样本当前基线登记，不跑完整性能矩阵：同机、同版本、隔离词库、相同动画/网络/温度条件，记录评分→下一词绘制与释义就绪。历史 47–107ms 仅作参考。

G5 集中比较修改前后，每个关键场景至少 3 轮×30 次有效切词（足够候选的隔离数据库），报告 P50、P95、最大值、原生/JS 耗时与 >50ms 主线程长任务。先固定并保留基线产物；不得选取更慢的旧包当比较对象。

建议阻断阈值：无音频及已缓存音频场景 P95 不高于当前同条件基线 + max(20ms, 基线的20%)；重复轮次出现新增 >200ms 切词，或新增任务造成 >50ms 主线程阻塞，定位后才能通过。若当前基线本身不达理想体验，单独记录，不能放宽新增回归限制。阈值是产品预算，G0 可依据仪器精度校准一次并写明理由，禁止失败后临时放宽。

语音按钮视觉反馈目标 ≤100ms；热缓存可听起音目标 ≤300ms；短词热模型未缓存目标 ≤1s，冷启动目标 ≤3s。均为待实测目标，不保证在所有设备成立。冷启动超标优先减少阻塞和修正状态提示，再评估模型/线程；不能用延迟切词换更快语音。

记录 APK 增量、模型安装峰值、空闲/合成内存和缓存上限。连续压力运行后应无持续单调内存增长、ANR、OOM；双音常驻或扩大缓存必须有测量理由。缺少性能数据时只标“功能通过、性能未验证”。

### 7.3 处置顺序

排序延迟：取消当前未发布规划 → 使用已存在候选顺序 → 保留待修复证据。语音竞争：取消过时任务、限制线程/并发、减少预热 → 必要时降级为按需初始化。新包失败：继续旧可用包。评分读取失败：展示可重试错误，不冒充空目录。数据库迁移失败：回滚事务、保留旧数据并阻止进入依赖新结构的功能。

内部开关将分组规划、发音服务、评分筛选分开，便于定位和回退；不是给用户新增复杂设置页。回退代码不可清空真实学习记录、词库和整个 localStorage；必要索引变更采用兼容策略，不删除评分历史。

- 切词：无语音、缓存播放、冷模型合成、连续口音切换、相似组规划、LAN发现并发。大库使用合成或经授权备份副本，不给真实词库注入压力数据。
- 前后台、锁屏、旋转、音频焦点丢失、耳机/扬声器切换、进程重启；避免后台突然播旧词。
- 集中音质样本建议 40 个词/短语×两口音，覆盖常见、易混、罕见、同形异音及多词短语；记录发音错误而非仅验证“有声音”。必要时成人用户集中确认音色和辨析可读性。

### 9.3 工程与交付链

最终从当前 package.json 和 tests/run-all.mjs 获取实际命令/数量，不照抄历史 61/98 项。执行严格完整测试，PREREQ/跳过不是通过；按影响补原生单元检查、生产迁移夹具、前端构建、Capacitor 同步和目标内部变体 Gradle 构建。没有依赖变化不重复 install，不盲目清缓存。

绑定：源码路径/HEAD/所选未提交文件哈希 → APK绝对路径/版本/签名/SHA-256 → 实际安装包与 WebView 资源版本 → 用户入口操作证据。仅构建通过不等于装机完成，HTML 模拟不等于原生能力通过。

分层报告“代码完成 / 自动化通过 / 安装验证 / 用户验收 / 发布授权”。任何关键门禁失败，不能以平均值、其他工作树结果或旧截图宣布完成。修复后重跑受影响门禁；只有修改波及全局前提时才重跑整个矩阵。

## 10. 常见失败与处置清单

| 情况 | 处置 | 禁止 |
| --- | --- | --- |
| Sherpa/模型/音素转换器不兼容 | 锁定可验证组合，保存失败证据；必要时调整同路线版本 | 悄悄改云TTS或固定词表，声称任意词已支持 |
| 覆盖安装后模型缺失/损坏 | 报告资产或 ABI 错误，保留应用可启动；用完整签名 APK 重新安装 | 把缺失模型报成“可用”，或静默改用云 TTS |
| 设备 ABI 不在包内 | 安装阶段或启动时明确不支持，改用 ARM 设备/对应构建 | 把 x86 模拟器失败说成模型问题，或删除 ARM 兼容层掩盖 |
| 英文读错/同形异音 | 记录可复现样例，检查规范化/模型/词义上下文 | 只因“产生音频”即判发音正确 |
| 正式评分保存失败 | 保留未提交状态，复用同 command 重试；筛选不提前变化 | 用内存评分假成功掩盖持久化失败 |
| 缺少正式评分/仅有巩固 | 保留在未学习范围；读取失败另报错 | 从阅读位置、手动已掌握或评分总数推造 fluent |
| 目录响应过期/词被删 | generation与身份校验丢弃旧响应，局部剔除/提示 | 以数值ID或旧数组下标强行展示 |
| 相似索引未就绪 | 正常到期顺序立即可用，后台增量生成后续片段 | 阻塞开始复习或整个后台重算占满CPU |
| 再学习词尚未到期 | 返回正常队列/展示下一到期时间 | 连续重复同词制造虚假熟练 |
| 对照词缺失/没有两词都作答 | 不开放完整答案对照，保留正常卡片 | 将尚未作答词的答案提前展示 |
| 性能回归 | 分离语音/排序/持久化测量，关闭引起回归的新增路径并修复 | 删除旧保护、取消落库、调慢动画掩盖 |
| 数据备份/还原不可验证 | 停止真实数据安装链，继续隔离验证 | 未经验证卸载重装或清库 |

## 11. 模型执行行为约束

1. 按本对话最新要求执行：成人、音标旁、评分衍生范围、无已学习标记、首页两列等高、筛选保持原样、必要验收在开发期、大验收最后；不得回到旧版标题旁或自动浏览即完成。
2. 未见 UI 必须进入同一 HTML 预览：评分筛选/空态、两列等高、形近组标签和可选辨析。不把技术调试开关塞进正式产品 UI；外部预览工具栏可标“演示”。
3. 本轮只有方案与预览授权。后续开发授权覆盖正常编辑和必要验证后持续推进；安装、真实评分、提交、发布、跨仓同步分别判断，不从工具可用性推导权限。
4. 优先复用现有 Vue 组件、API、迁移、身份和预取；仅在职责清晰的边界增加模块。不复制三套发音服务、不建新任务队列框架、不顺手升级无关依赖。
5. 不改或丢弃既有用户修改。操作前看目标文件差异；不整仓覆盖、不硬重置、不清理无关文件。一次修改只纳入相关文件。
6. 重要事实有源码/官方资料/实机证据；明确区分已验证、设计初值和待验证。儿童结论不能包装成成人效果，工程预算不能包装成研究结论。
7. 不在 UI/评分关键路径调用 AI、全词库相似计算、模型加载或网络下载。新任务必须遵守有界并发、取消令牌、缓存上限和线程隔离。
8. 必要小验证只回答当前风险：原生能否离线出声、评分筛选是否准确、队列是否漏重、切词是否明显回退。禁止每个文件改动后跑全量 strict/完整APK/所有截图矩阵。
9. 测试断言与最新需求冲突时，依据用户要求及复现修正；保留有效保护。不能仅为全绿删除失败用例、改阈值、吞异常或将PREREQ当通过。
10. 真实用户词库默认只读；评分/查询/必要迁移压力测试用隔离库或获批备份副本。记录环境、目标包和实际路径，不以代码目录隔离代替数据隔离。
11. 已通过且输入/实现/环境未变的证据复用；失败两次同形命令/补丁后换方法并记录原因，避免循环试错。未知平台API先查官方资料，不猜接口。
12. 正式文案简洁、准确、一致；按钮用查看辨析、返回复习。不得增加完成学习按钮或已学习徽标。状态用正在合成、正在播放、发音暂不可用。避免学过了、再来一遍、搞定等口语和无法证明的承诺。
13. 不宣称断网工作直到真实设备以未缓存词验证；不宣称性能通过直到同条件测量；不宣称用户验收直到收到用户反馈。
14. 方案/预览交付后停止在本轮范围，不自动开始实施、发送发布消息或长期监控。完成/阻塞按已配置 ClawBot 规则通知，只报告实际发送结果。
