## 3. 逐项整改（已批准规格；其中现状证据为初查快照）

### R1：Part B 结构、阅读题干/选项错位与排序信息缺失（高优先级）

**证据。** `frontend/public/internal-question-bank.esq` 中 `papers/2016.json` 的 `local.english-practice.2016.unit6` 类型为小标题匹配，七条真正小标题混在正文开头；正文只保留到 `42 ______.42.`；候选 B/D/F 分别为 `43.`、`44.`、`45.`，其他候选是正文段落。Windows 开发库中同一稳定键也是该结构。

**整改。**

1. 对照原卷恢复七个小标题 A–G、导语和 41–45 五个位置对应的完整正文；删除重复空号；同步维护 passage、content_blocks、shared_data.candidates 和每题 options，逐题校对答案稳定键。
2. 修正 Android `document-import.ts:396` 附近 `parsePartB` 和 Windows `services/docx_parser.py:1481` 附近逻辑：按题型识别标题列表和正文位置；兼容实际标签/段落形式，证据不足时进入需校对草稿，不自动截取最后七块冒充候选。
3. 增加结构校验：候选不能只是题号，候选身份唯一、空位和题号一致、正文不被截断；按小标题匹配/段落排序/插入题分别判断，不用一个长度阈值误伤合法长选项。

### R2：完型空号位于横线上方（高优先级）

**证据。** `ContentBlocks.vue:23` 只识别 `{{blank:N}}`，但包中内容块保留 `1 ______` 等旧格式；PracticeView 优先使用内容块，绕过另一条兼容旧空号的文本渲染路径。已有 `.passage-blank` 样式并非全部缺失。

审计 F032 将包内覆盖范围确认到全部 34 个完型单元；WD 实际库仅 17 个完型单元有 content_blocks，其余走纯文本路径，不能将 34 直接写成该库运行命中数。F004 为 2015 英语一第 1 空重复，F006 为 2020 英语一 Part B 的 41–45 标记重复串接，均纳入数据清理与对应题型的空位规范化。

**整改。** 新导入/导出统一空位语义；旧数据在渲染入口兼容转换。限定完型题型及该题实际空号集合，避免将年份、正文数字和 Part B 固定位置误判为空。内容块与纯文本最终使用同一空位组件。

重复空号先按单元和空位证据精准处理，不能用全局连续数字去重。Part B 的重复标记单独按其题型规则修正，完型“序号在线上方”的样式不自动套用到排序固定段；各题型仍须保留自己的作答语义。

目标示意：`word   1   word`，其中数字 1 居中位于独立横线正上方；数字与横线不可跨行拆散，行高不压住上下文。保留“第 N 空”的无障碍标签，不通过修改题干字符宽度凑位置。

**验收。** 新旧 ESQ、纯文本和内容块、单/双位空号、长段换行、字号放大均居中不重叠；不改题号、答案或选项顺序。以原卷截图确认具体间距。

**整改。** 用 packageId + question external_key + option stable_key + 旧内容指纹定位，校对后仅改选项文本。排查 DOCX/文本解析中下一题题号粘连上一选项的边界条件，使用定向样本回归；不得全局删除选项末尾数字。扩展扫描同包中孤立题号、全角句点和异常尾缀，逐条确认。

已确认范围扩展至 F003 的 2010 英语一完型第 1–6 题稳定 D 尾部题号、F026 的 2011 英语二 Part B 候选断词/连写、F030/F031 的 2012/2015 英语二 Part B 尾部 Directions 残留。F005/F007/F008/F027/F028/F029 分别涉及孤立字符、疑似撇号损坏、词界/段界与 O/0 混淆，作为强关联校勘项保留；部分异常已存在于来源稿，不能仅靠重跑导入解决，也不能让模型猜测后批量写回。

**验收。** 顺序显示、随机显示、旧会话恢复下均为正确单词；稳定键和评分不因显示字母变化而改变。合法数字选项保持。

### R4：一次重试处理全部等待翻译词（高优先级）

**证据。** 四树 VocabularyView 的重试均针对 selected.id；Android 页面入口还会触发一批待译任务，但重试并非全量。Android/Windows 均有 100 条限制；Windows worker 单次领取至多 100 条，批量 8；Android worker 批量 40，当前模型预算 2400 tokens。增加词形/例句后不能沿用不加评估的批量大小。

**目标语义。** 点击“重试全部待翻译”，服务端选择当前用户单词本的所有有效待处理词，不受搜索框、分页或当前选中项影响。包括 pending、failed；queued/inflight 去重后继续，不重复请求。保留既有题库权限边界，不跨用户或越过隔离的数据范围。若界面当前按题库筛选，仍清楚标明该操作作用于整个单词本。

**整改。**

1. 建立专用的全量重试操作和持久任务状态，服务端选择目标；分批消费直到此次目标全部进入成功、明确失败或可恢复暂停状态，不因 LIMIT 100 遗留尾部。
2. 重复点击幂等，已有 worker 接续工作；每词失败隔离；断网、退出、后台/重启后可恢复，Android 不承诺系统杀进程后继续执行模型请求。
3. 不配置模型、认证失败、限流和配额耗尽时给出真实状态并有界停止/退避；不能无限付费重试。UI 显示待处理、处理中、完成与失败数量，重新进入页面能恢复进度，不只依赖约一分钟的固定轮询。
4. 保留手动编辑门控，禁止批量把 user_edited 清零。手动完成释义但缺少词形的词走“补全缺失字段”，不与全文重译混用。
5. 批次大小按输出预算和上下文长度确定；补齐词形/例句后用少量真实模型响应验证截断、漏项和成本，再定默认值。

**验收。** 0/1/100/101/250 个混合状态词；多次点击、部分失败、页面退出重进、应用重启均不漏词不重复并发；手动内容不被覆盖；状态统计一致。

### R5：辨认词形并提供显示开关（中优先级）

**证据。** 现有模型返回 lemma 和 partOfSpeech，没有明确的当前形态、形态集合或可信度。`similarForms` 现指“形近词”，不能挪作过去式等词形字段。现有显示配置在 Android 横竖屏及复习页并未完全统一。

**整改。** 保留用户选中的 surface form；新增 lemma、当前形态标签（原形/过去式/过去分词/现在分词/复数/比较级等）、适用词形列表和歧义状态。词形由模型结合上下文判断，无上下文的 `read`、`saw` 等允许多解或“无法唯一判定”，不能强行给唯一答案。新增词形不更改 normalized_term 身份、不自动合并原词和屈折词。

在 Windows 设置、Android SettingsView/MobileSettingsView 的词汇显示设置加入“显示单词词形”，建议默认开启；详情与复习答案区共同遵守并持久保存。复习揭示答案前不额外暴露词形提示。例：`went → go · 过去式`；可显示 `go / goes / went / gone / going`，形近词仍独立。关闭只控制显示，不删除已生成信息或触发重新翻译。

**验收。** 规则/不规则动词、名词复数、比较级、同形多义和无需屈折的词；开关跨页面/旋转/重启保持；原词、用户释义及复习计划不被改变。

### R6：无真题完整上下文时补模型例句（中优先级）

**证据。** PracticeView 通过最近的 data-vocab-text 容器提取文字，选项里的单词也可能成为 context_sentence；当前模型协议不生成例句，且未标注来源类型/上下文有效性。

**整改。** 记录来源 passage/question/option 和实际选中位置，判断是否有可用完整句子。来源是选项不必一律排除，但孤立词、短语、题号不能充当真题例句。若同词已有有效真题句，优先使用；确实没有才生成 1 条简短自然英文例句及中文译文，尽量使用当前形态与词义。

模型例句用独立字段存储并标明“模型例句”，不写入真实遇见记录、不伪造年份/篇目、不增加 encounter_count。无上下文时不输出虚假的“本文语境释义”，使用通用释义。后续出现有效真题句后，优先展示真题句，并按上下文版本更新相关释义。

**验收。** 完型孤立选项、短语、完整句选项、正文句、同词多来源、模型失败和旧词补全；详情及复习页均不把模型例句标为真题。

### R7：真题中的遇见只展示最新一条（高优先级）

**证据。** Android 竖屏和横屏、Windows 详情均 v-for 所有 occurrences；最新句按本地 id 倒序，局域网导入的旧记录可能获得更大 id。重复加入会新建遇见记录。

**整改。** 建立所有页面共用的“最新有效真题例句”投影：按实际遇见时间倒序，以稳定同步键作同秒确定性排序，筛去空内容/孤立词；相同句子和来源进行保守去重，不大幅删除有语义的标点。优先选最新有效句，而非最新一条无上下文选项。

“最新”指最近一次实际遇见，非年份最大、导入时间最新或本地行号最大。详情只展示 1 条对应真题句、来源和匹配该句的语境释义；旧释义不能冒充新句的释义。无有效句时隐藏真题板块，按 R6 展示模型例句。内部遇见历史、计数与同步记录保留，不为隐藏旧句删除用户历史。

**验收。** 同句多次加入、两条不同句、离线同步旧句、同秒记录、最新记录为孤立选项；四树详情和复习答案区只显示正确的一条，无重复。

### R8：Android 左右滑动切换篇目（中优先级）

**证据。** PracticeView 已有 switchUnit 与答题卡跳转入口，但未发现左右滑篇识别；竖屏另有拖动分隔条。

**整改。** 左滑下一篇、右滑上一篇，两种方向均接入同一个受边界检查的导航动作；只在当前练习会话包含的篇目间切换，第一/最后篇不循环，不自动新建会话或提交试卷。单篇随机练习保持单篇边界；另开新篇属于独立产品功能。

建议初始识别阈值为横移至少 64 CSS px 且大于纵移 1.5 倍，待一次手机/平板体验微调。优先允许纵向滚动；文字选中、长按取词、按钮/输入框/滑条、可横向滚动区、分隔条、弹层、系统边缘返回、多指手势不触发滑篇。每次手势只切一篇，避免触发遗留 click。

切换沿用已选答案、计时与导航状态；正确处理在途保存失败、音频生命周期、滚动位置、快速连续操作和旋转。左右滑动与点击篇目按钮产生一致结果，不能为实现手势另建一套提交或计时规则。

**验收。** 双 Android 版本在手机与平板横/竖屏各执行前后切换、边界、滚动不误触、长按取词、拖分隔条、保存失败和旋转；Windows 共享导航不回退。

### R9：今日到期队列避免尾部长期饿死（高优先级）

**证据。** 当前到期筛选仍按最近七天遇见、高频、遇见次数等排序，进入复习重置到首项。每天重开加上新词/重学词前插，会长期挤占尾部。各 Windows 版本的评分后索引处理不同，必须分别适配。

**推荐规则：可续接的公平队列。**

1. 队列与普通词表排序分离。首次建立时：未复习词优先，同组按等待时间最久；已复习词按最早上次复习，再按到期时间和稳定键确定顺序。只纳入 ready 且已到期的有效词。
2. 持久保存未完成词的有序稳定键。退出/跨天重进继续队首，新到期词追加队尾，不因最近遇见或高频挤入前面。评分保存成功才移出；失败留在当前词。已删除、未到期或其他设备已完成的词重新检查后跳过。
3. 短时重学与普通到期队列分开：建议每完成 4 个主队列词最多插入 1 个已到期重学词，主队列为空则正常重学。到期前不强行练；再次答错的词不能持续霸占同一位置。该配额是建议初值，不改既有评分间隔算法。
4. 首页“今日到期”和单词本同名入口共用队列服务，明确保持入口现有当前题库/全部范围；搜索筛选不应悄悄改变正式复习集合。强化练习保留独立模式，不混入到期完成统计。
5. 第一版建议队列次序按设备和复习范围本地保存；同步真实复习记录后对账，使用稳定词条键而非本地 id。暂不增加跨设备实时共享游标，以免扩大同步协议。换设备时按已同步学习记录重新建立公平队列；此边界应在交付说明中写明。

**验收。** 构造 100 词每天只练 10 个、多日退出重进、持续新增、部分重复答错；原尾部词按队列推进得到机会。测试失败评分、不重复计数、删除与跨设备同步对账。不能承诺每日任务一定清空；新增速度超过学习能力时积压仍会增长，但后到词不能持续越过已有等待词。

## 5. 词汇模型、存储与同步协同

R4–R7 应先定义同一字段/状态契约再改 UI，避免分别开发后出现混乱。建议新增词形对象、例句对象、来源类别、上下文有效性和语境绑定版本；具体列/JSON 结构以现有迁移风格和同步序列化能力确定，不在计划中提前钉死。

- 模型 JSON 必须校验 entryId、类型、枚举、长度和缺项；无真题上下文时不强制 contextualMeaning 非空才能判定成功。输出截断或部分缺失只影响对应词，不覆盖已成功词。
- 新增缺失字段的补全队列与基本翻译状态分开，保留 ready 词的可复习性。保护用户编辑字段及请求期间发生的更新，按内容版本/时间戳做条件写入，过期响应不能覆盖新语境。
- 旧词按需或明确批量补全，不能升级即全库收费重译。旧遇见记录来源不明时保守判定，无法确定时不编造真题上下文。
- 数据库采用增量迁移；对 LAN 导入/导出/列过滤/合并/能力版本逐项核对。新旧端互通不得用缺省空值擦掉新字段；旧端缺字段时应保留或明确阻止不安全操作。
- 模型例句不参与真实遇见计数；队列运行状态不等同于可同步学习成果，不把一个设备的“处理中”当作其他设备永远无需处理。
- 数据备份、恢复和旧客户端兼容必须使用合成或备份副本验证；旧 APK 能安装不代表数据库能降级。
