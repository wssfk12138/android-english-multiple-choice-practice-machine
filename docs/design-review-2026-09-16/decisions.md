# 完整待决定事项

本清单不是要求你重新决定所有旧问题。已明确的功能保留、删除范围和菜单修复见 README，不再提问。推荐项只是设计建议，**没有自动生效或授权开发**。

## D01 单词本下半区：每行显示什么

**现状与问题：** 当前行包含词条、遇见次数、释义、词性和状态，历史平板截图里一屏列表只能看到约三行。需要决定扫描列表时优先看词、发音还是意思；当前无法以旧截图高度承诺改后能固定显示几行。

| 选项 | 界面结果 | 收益与代价 |
| --- | --- | --- |
| A 词条 + 状态 | 最小行高约 56 CSS px，重点星标随词；释义、音标、遇见次数进详情 | 更紧凑，但选词前看不到发音和意思 |
| **B 词条 + 音标 + 状态（推荐）** | 最小行高约 64 CSS px；详情保留释义和次数 | 保持学习导向，避免列表提前暴露释义；比 A 少一些行 |
| C 词条 + 释义 + 状态 | 最小行高约 76 CSS px，长释义自然增高 | 找熟悉含义更快，但列表更高，也会提前看到意思 |

上述数值是待实机校准的设计起点，不是通用标准。所有选项保留“遇到次数”，只是从列表移入详情。**推荐 B**，不会影响数据；后续可换布局。预览 01 顶部 A/B/C 可比较。注意：这是“单词列表”的 B，与你已确认的“单词显示 B 三组”是两个不同问题。

## D02 左右两栏的宽度分配

**现状：** 历史列表与详情的可比宽度约为 374 / 527 CSS px，旧报告曾把横屏 753 误当宽度。应以内容和实测 WebView 为准。

- **A 有上下限的列表宽度（推荐）**：先以约 260–300 CSS px 试排，窄处降到 240，剩余空间给原句与释义。列表稳定，长词需换行；不强行拉满空白。
- B 按可用内容宽约 30% 分配：超宽屏更舒展，但列表会随屏幕越变越宽，可能重新出现大块空白。

两者均在双栏容不下内容时回到现有“选中行下展开详情”的模式，不新建详情业务。预览调整面板可调宽度与比例方案（宿主支持时），也可查看[比例版截图](previews/vocab-ratio.png)。无需把精确像素当作你的产品选择。完全可回退，无存储影响。

## D03 详情中补充栏目默认展开还是折叠

**现状：** 当前共享内容有可展开栏目，默认展开；真题原句是独立内容区。

- **A 保留已启用栏目展开（推荐）**：可直接阅读词形、笔记等已有内容；长词条需要更多纵向空间。与当前行为接近。
- B 默认折叠补充栏目：释义和原句优先，点开后看词形、辨析、记忆提示和笔记。更短，但多一次操作，可能忽略个人记录。

开关控制“是否显示”，折叠控制“是否展开”，两者不可混为一谈。保留“展开已启用栏目”；空字段沿用当前隐藏规则。预览调整面板可对比，可回退且不删除记录。

## D04 每日一背：答案连续单栏还是宽屏双栏

**已确定：** 单词下的独立音标保留；真题原句和答案必须左对齐；常用释义处不再重复音标、词性。

- **A 连续单栏（推荐）**：上方单词与音标，下面依次是释义、原句与出处、已启用补充栏目，底部三个评分按钮。阅读顺序自然，接近你要求恢复的排版；内容多时向下滚动。
- B 宽屏双栏：左侧释义和补充内容，右侧原句与出处；窄屏仍单栏。较短词条能利用宽度，但两栏高度常不一致，需要左右扫视。

不会为了让所有答案塞进一屏缩字，按钮不能压住最后一行。预览 02 先点“显示释义和原句”，再切布局。此处决定不改变正式复习计划和评分算法，可回退。

## D05 个人记录名称：我的笔记 / 我的卡片

**已确定：保留功能。** 源码的真实字段是 note，当前名称为“我的笔记”，可以编辑并保存。历史截图或旧库里暂时为空不能作为不存在的证据。

- **A 继续叫“我的笔记”（推荐）**：与编辑字段一致，无迁移和学习成本。
- B 统一改叫“我的卡片”：符合你最后用词，但可能让人理解为整张单词卡。若选它，只改可见名称，各处统一，字段和数据不改。

预览默认 A，调整面板可比较名称（宿主支持时），也可查看[“我的卡片”与折叠栏目截图](previews/vocab-card-collapsed.png)。名称可回退。**不选择也不删除功能。**

## D06 设置首页是否保留“已开启 N 项”

这是状态摘要，不是“用小字解释标题”的文案；故不能替你按冗余批注删除。

- **A 保留，放在右侧一行（推荐）**：进入前能知道配置概况；不再放标题下占第二行。
- B 不显示计数：入口更简洁，需要进入单词显示页看勾选项。

不影响 11 个设置项与原有保存值。预览 04，调整面板可切计数，可回退。

## D07 设置首页的分组排列

- **A 单列分组（推荐）**：外观与显示 → 题库与数据 → AI 与模型 → 设备与维护 → 帮助。稳定、容易找，和平板竖屏保持一致；页面稍长。
- B 宽屏双列：保留相同分组和全部入口，减少纵向滚动；读取顺序横向变化、组数和高度不对称。窄屏自动单列。

主题开关都直接在首页；侧栏夜间切换都保留。词条维护都放“设备与维护”。预览 04 可比较。无数据风险，可回退。

## D09 API 配置：连接信息如何收紧

**已确定：** 标签与控件同行、去重复标题、常用操作聚拢、目录筛选可见。不是讨论要不要修复。

- **A 单列短表单（推荐）**：名称、协议、地址、密钥按顺序对齐；限制无意义的输入宽度；下方模型与强度操作条，目录单独一段。最稳定，保留较长地址可编辑空间。
- B 宽屏两组并排：左边名称/协议/地址，右边密钥/默认状态。屏幕足够宽时较矮；密钥管理展开后左右高度不齐，复杂名称可能换行。

预览 06 可比较，省略号和密钥管理可展开。建议默认 A；不为了“一行”截断标签或隐藏强度的不可用原因。所有配置仍可停用、新建、编辑、删除；不改变密钥的原生保存方式。可回退，无协议更改。

## D10 全局控件密度

- **A 适中紧凑（推荐）**：普通操作保留至少约 44–48 CSS px 的有效高度，设置行约 56，输入文字不刻意缩小；减少空白靠布局和内边距。数字是设计起点，设备上核对真实触控尺寸与字体缩放。
- B 更宽松：按钮与输入更高，列表和设置每屏内容更少；对大字号或精细点击不便的人更友好。

不会提供小到难点的“极限压缩”版本。预览默认 A，调整面板可比较 B（宿主支持时），也可查看[宽松版截图](previews/settings-roomy.png)。B 整体加间距与最小高度，不增设产品密度设置。可回退。字体放大测试不能用桌面修改根字号冒充 Android 系统字号验收。

## D11 首次载入卡顿接下来怎么推进

- **A UI 实施时并行做性能测量，依据结果另列最小修复范围（推荐）**：能尽早分清数据库、桥接、后台任务和渲染的占比；增加一次设备测量工作，不预先大改逻辑。
- B 先完成选定 UI，性能继续作为独立待办：设计交付更聚焦，但更换布局后仍可能卡顿。

选择 A 不是授权任何性能重构。当前没有证据支持“SQL 已排除”或“模糊就是唯一原因”。测量本身不改变用户学习数据；需要临时埋点时明确范围与移除方式。参见 README 第二层。
