## 必须更正的旧判断

1. **PC SQLite 快，不等于 Android 数据库已排除。** PC 样本中 SQL 小于约 2 ms，只能描述那个样本；Android 查询、插件排队、桥接序列化、数据量和渲染应分段测量。
2. **没有证据确认模糊效果是唯一或主要根因。** 它是需要同设备开关对照的假设。
3. **sw753dp 不是横屏网页宽度。** 历史物理尺寸 2560×1600、密度 340 的名义结果约为 1205×753；窗口回执另有 w1205dp / h721dp，最终仍需读取 WebView 的实际内宽高。
4. **CSS px、dp 与截图像素不可无条件等同。** 2.125 是那次密度的名义比例，不能套所有页面；根字号模拟不等于 Android 系统文本缩放。
5. **宽度与溢出重新分类。** 可比历史列表/详情约 374/527 CSS px；竖屏行下展开属于已有设计。固定最小高度 480 与错误视口推导不足以证明实际溢出；1–2 个截图像素差也可能只是取整。
6. **17 套、102 单元、765 题没有算术矛盾。** 17×6 与 17×45 可同时成立，不据此列统计 bug。
7. **模型目录过滤已存在。** 问题是折叠隐藏与可发现性，整改为显式呈现。
8. **个人记录真实存在并能编辑。** 最后一条要求保留，早先删除意向作废。
9. **旧“27 项”实际为 28 项。** 分类数量是 7+2+6+7+4+2；逐项去向如下，不机械把 28 个工程细节都重新推给用户。
10. **外部项目排名不作为本轮依据。** 一份调研未完成；没有重新验证的星标/热门度不能当作当前事实或全面比较。
11. **数据库队列说法要准确。** 不能把 rows/row/run 都说成进入同一 JavaScript 串行队列；事务路径与普通读取不同。单连接、原生插件线程等仍可能产生实际串行等待，应现场测量。
