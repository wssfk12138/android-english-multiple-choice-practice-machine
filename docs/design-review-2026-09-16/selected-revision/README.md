## 横屏边界

新布局、图标与按钮只在 Android 横屏生效，利用现有平台和方向标记，不只靠宽度判断；竖屏视觉保持原样。预览窄窗口重排仅为对话评审，不是竖屏设计。

显示配置仍共用原数据；每日一背隐藏词形/笔记只限制横屏展示，不清空数据、不重置全局选项。自动保存、分析持久化、加载读取修复属于共享底层行为，不建立两份数据。旋转不丢复习进度、草稿、错误或未完成写入，不重复评分/启动补缺。分析新页本次只设计横屏；竖屏入口和原显示方式保持现状，读取同一报告库。

## 每日一背、设置和图标细节

- 每张卡显示单词时，按该词实际答案为常用释义和原句留位；未揭示区域隐藏且不可聚焦、不可被辅助技术提前读出。揭示只改变可见性，卡片和底部按钮不跳动。长句、空字段和异步内容须验证；当前卡片内容宜在展示前确定，避免揭示时再补载。空字段不用示例内容填充，三种评分规则不变。
- 合并页保留核心信息 4 项、补充学习 6 项、个人记录 1 项，保存现有值；设备 6 项开启只作预览初始示意。按 R05 只逐项开关，按 R04 在入口右侧保留开启数。继续补缺/暂停、重试失败词条、检查模型配置同行，状态变化不挪位。
- 设置仍按 A 单列分组；用户已明确确认只改入口名并合并内容。默认亮色，不跟随预览宿主自动变暗；圆钮右开左关，用户选择自动保存。无主题偏好时采用亮色，升级时已有明确偏好暂按保留设计，避免静默覆盖用户选择。
- 图标采用填空文本、书页、有序段落、耳机，统一线条与柔和配色。只换图标资源，保留首页网格、卡片尺寸、间距、背景、文字、箭头、顺序；听力沿用原数据条件，不增加空入口。

### 本轮比例基准

以下为相同 973 CSS px 预览窗口、默认示例内容与字号的实测目标。卡片“缩小 20%”按宽高分别乘 0.8 执行，文字字号保持可读；不是把整个画面缩放。

| 对象 | 修改前 | 本轮目标 |
| --- | ---: | ---: |
| 每日一背卡片 | 850 × 540.84 | 680 × 432.67 CSS px |
| 单个评分按钮宽 | 260 | 156 CSS px（60%） |
| 按钮到预览内容底边 | 54 | 75.6 CSS px（1.4 倍） |
| 普通设置行高 | 56 | 39.2 CSS px（70%） |
| 深色开关行高 | 61 | 42.7 CSS px（70%） |
| 不使用密钥轨道 | 54 × 32 | 37.8 × 22.4 CSS px（70%） |

常用释义下间距从 26 收至 8 CSS px，上方单词区和标签留白同步收紧；三个按钮居中，释义揭示前后卡片保持同高。长原句、大字或窄评审窗口允许卡片自然增高，不截字；同一张卡揭示前已为实际内容留位。设置在触摸设备上将不足 44 CSS px 的点击目标保留到 44，行内留白仍按收紧方案；密钥小圆钮也保留 44 × 44 点击范围。实际平板屏幕底部距离须在获准实装后连同安全区复测，当前数值只证明预览比例。

## 模型与 API Key

保留 SettingsView 原折叠摘要：图标、名称、默认标记、地址摘要、模型显示数、箭头、启用开关与更多菜单。进入页默认全部收起，不使用上一稿新式折叠卡片。展开左列连接信息，右列命名密钥，下方一行依次为默认模型、推理强度、测试连接、设为默认，缩窄两个下拉框为最后一项留位；移除“模型目录”标题，保留搜索、筛选和模型列表。

删除的是重复的“请求地址”明细；**API 地址（服务基础地址）输入保留**，用于指定服务，实际路径仍按原协议生成。

API Key 标题同行放“不使用密钥”圆钮，不另占一行；仅此圆钮可见尺寸缩至上一版的 70%。通常常显两行，其余放“其他密钥（N）”折叠区；若当前项在额外记录中，常显区域须标明当前名称。采用本地 OpenCodex 命名密钥管理的操作思路，未读取真实密钥。

密钥行显示别名、遮蔽占位、当前状态、改名/删除。接口只提供 id/name，不伪造真实尾号。添加展开名称与密码框，改名原位编辑，删除确认。不使用密钥时不删除原有密钥。新增密钥保留明确“添加”动作，但无需再点“保存配置”。不增加明文查看、复制、配额或轮换。

## 自动保存方案

预览只模拟状态，以下为后续实际持久化要求：

| 内容 | 保存与失败处理 |
| --- | --- |
| 开关、选择框、默认配置/模型、强度、模型可见性 | 有效修改立即排队；同值不重复写入 |
| 名称、API 地址等文本 | 停止输入约 500ms 后保存，失焦立即提交有效值；不完整地址等保留草稿并提示，不覆盖最后有效值 |
| 密钥 | 添加时写原生 SecureStore；改名完成自动保存；选择立即保存；删除仍确认 |
| 反馈 | 紧凑显示保存中/已保存/失败重试；真正持久化成功后才显示已保存 |
| 并发与离页 | 按配置协调串行写入，最新有效输入为准；旧响应不覆盖新值，离页/旋转保留待写内容及草稿 |

敏感值仅进 SecureStore，不进入 SQLite、日志、源码或预览。自动保存不自动测试、不按击键请求模型；测试、补缺、删除仍由用户主动触发。

## 错题按钮与分析记录

现场内测版 alpha.90 / code 90；横屏重做边界 [2063,799][2184,903]，为 **121 × 104 物理像素**。目标宽 121 × 1.20 = **145.2 物理像素**，实装允许 145/146。密度 340 下名义逻辑宽 68.3294 只作起点，未取得 WebView 实际缩放，不宣称像素级还原。

重做→分析→删除同排常显，左侧文字收窄换行，展开箭头随文字区调整，保留年份/篇目卡片层级。R03 已选图标配两行四字标签，不省字、不再加宽。未分析时显示“分析”，已有报告始终显示“查看/分析”，即使已允许重新分析也不替换查看入口；“重新分析”放在独立分析页内。分析状态共用一个位置，不增加第四按钮。

查看分析进入独立页，生成进度、错误和完整报告均在该页显示，首页不再展开正文。保留“完成下一次正式重做后才能重新分析”的原规则；浏览历史不调用模型。返回恢复原列表状态。

### 已有持久化与必要补齐（R07 / R08 已确定）

已核对当前 Android 源码：wrong_analysis_reports 存报告、模型、时间、范围和 input_snapshot；wrong_analysis_states 关联最新报告；状态查询从 SQLite 读取正文，新分析使用 INSERT。**本地持久化已经存在，跳过另造长期保存系统，以及换机、卸载恢复或设备外备份工作。** 这是一项源码核验结论，不替代真机重启验证。

当前仍需完成：

1. 保留的错题可在任何时候通过“查看分析”进入独立页，读取已有报告不请求模型。现有界面在允许重新分析时会替换入口，需修正；页内“重新分析”沿用完成正式重做后的原资格规则。
2. 复用已有报告表提供按时间选择历史的读取；成功的新分析不覆盖旧记录；失败、中断不影响已保存报告，不对保留错题的报告另设自动过期规则。
3. 删除原错题时关联分析一起删除。当前路径只删状态未删报告，后续补齐同一删除生命周期中的报告处理，不建设“原题已删除”的永久分析归档。沿用现有回收站规则：从正常界面同时移除，恢复时一起恢复，到期/彻底删除时一起清理。
4. 核查批量删除、多篇共享范围报告与旧关联数据，避免串篇误删和孤立报告；这属于实现核验，不增加产品选项。必要快照仅复用原有字段，不扩展为独立备份体系。
5. 验收范围是当前应用保留数据期间，离页、重启以及有权重新分析后仍能阅读旧结果；不承诺卸载、清数据或换机后的恢复。

## 首页、单词本加载修复方案

重新阅读[9 月 14 日调查](../../context/history/2026-09-14-android-first-load-lag-audit.md)。旧报告“已排除 SQL/数据量”的结论过强，本方案据其方法限制收窄结论，不改写历史原文。

| 证据层级 | 线索 | 下一步 |
| --- | --- | --- |
| 历史测量 | PC 的 node:sqlite 读取 9 月 13 日真实设备快照，热点 SQL 多在 2ms 内 | 不能外推平板 SQL、插件排队、桥传输与解析耗时，需要真机分段测量 |
| 历史源码调查 | 首页挂载/启动完成两条刷新路径，待办重挂载，重复状态查询 | 测必要刷新条件并消除冗余，不能漏修正完成后的有效刷新 |
| 历史源码调查 | 启动读取并校验约 3.85MB 内容修正清单 | 核对版本门控和已修正状态，避免重复解析，不跳过首次校验 |
| 历史源码调查 | 单词本先等翻译调度再读列表，补缺同期启动 | 前台先读；后台翻译/补缺分批让出资源，缩短数据库通道排队 |
| 历史源码调查 | SELECT * 和批量出现记录含长文本 | 必要时减首屏字段、按需读详情，缓存有明确失效条件 |
| 待验证假设 | 横屏大面积模糊增加合成开销 | 先帧时间对照，证实后才局部优化，保持当前系统风格 |

后续按下列顺序执行：

1. 核对安装包/源码版本。同设备同数据测首页冷/热启动、单词本首次/重复进入、后台任务空闲/忙碌，重复采样记录中位数和慢样本。
2. 拆分挂载→请求→数据库排队/执行→桥传输/解析→首个内容帧，另计修正清单、请求次数、评分后下一词耗时及帧时间。
3. 优先修前台时序、重复请求/重挂载和后台批次；按证据再减返回量、加正确失效的缓存。索引、日志模式、大范围数据库修改不作默认套餐。
4. 模糊效果先做帧时间对照，有显著收益才调整横屏局部。不用缩字、裁内容或取消功能掩盖慢加载。
5. 同条件比较修复前后，验证统计、翻译、补缺、复习进度与题库切换。目标是明显缩短等待并消除已证实重复工作，具体时间门槛在真机基线后确定。

本轮无新增真机性能分段计时、无性能代码修改，不能称已修复。共同数据链路可能改善竖屏耗时，但竖屏视觉不变。
