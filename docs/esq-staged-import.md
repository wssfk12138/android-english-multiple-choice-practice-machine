# ESQ 大题包导入实现说明

两版 Android 客户端（内测版与公测版）使用同一套 ESQ 导入流程，前端显示保持不变。

## 导入流程

1. Android 文件选择器只把已选择文件的名称和大小交给原生插件校验；原生端以 64 KiB 分块复制到应用私有目录，并计算 SHA-256。
2. 复制完成且 fsync 成功后，原生端按题包文件逐项解析，把试卷、篇目和题目写成带 SHA-256 尾校验的暂存记录。JavaScript 只读取摘要或单条记录，不再把整个 ESQ 文件转换为一个 Base64 字符串。
3. 暂存任务保存来源文件、请求回执、解析状态和可校验的记录。应用重新启动时会扫描有效回执，从保留的暂存数据继续；记录损坏时会从已校验的源文件重建。
4. 正式入库在 SQLite 独占事务中逐题发布。任一题、选项、媒体引用或索引写入失败，事务整体回滚，导入草稿保留，下一次可重试；提交成功后才确认并清理请求回执，源文件和记录仍保留用于恢复校验。

## 约束

- ESQ 压缩包上限仍为 2 GiB；单个 JSON 64 MiB、全部 JSON 256 MiB、解压总量 8 GiB、条目 10,000、压缩比 250、试卷 100。
- 这版验证了 CET4 35 套试卷/1,825 题和 CET6 43 套试卷/2,365 题的真实题包，以及接近 2 GiB 的媒体型压缩包。
- 暂存源文件目前不自动垃圾回收；异常终止留下的无效 .part 或媒体暂存需要后续清理策略。实际 Android 文件选择器生命周期和真机强制停止尚待设备验收。

Windows 端题包格式和导入路径未随本改动改变。
